# Текущее состояние проекта (2026-08-12)

## Что работает

### Ядро
- **Ray-marching горизонта**: 3600 лучей, кривизна Земли + рефракция (k=0.13), Web Worker
- **Гребни силуэта**: локальные максимумы угла вдоль луча по корзинам дистанций (`CREST_BOUNDS`) — только они реально видны как линия силуэта
- **Terrarium DEM**: глобальный онлайн-слой (AWS), z9–z12 по дальности луча
- **Пики**: 692 355 вершин из planet-260803.osm.pbf (включая 4984 вулкана), 115 регионов, двуязычные названия
- **Проекция**: азимут/возвышение → экран, вертикальный FOV выводится из пропорций холста

### UI
- **Canvas 2D**: контуры силуэта (двойная линия: чёрная сверху, белая снизу), шкала азимутов, подписи вершин под углом 60° с первой буквой над вершиной
- **Стиль под камеру**: никаких заливок и плашек — только контрастные линии и текст с обводкой, чтобы оверлей совмещался с реальным кадром
- **Приоритет подписей**: `ele · (1 + 0.4·exp(−d/40км)) · w(изоляция)` — высота, близость и «интересность» вершины; вытесненные соседи собираются в «+N»
- **Изоляция вершин**: расстояние до ближайшей более высокой (заменитель prominence, которого в OSM нет). Из тесной группы подписывается главная, одиноко стоящая гора не проигрывает побочному пику соседнего массива. 49 тыс. вершин — 89 мс (ALGORITHMS.md §5)
- **Скрытые вершины**: вершине не хватило до гребня <400 м — подписывается серой пунктирной выноской без кружка-маркера. Подпись поднимается над загораживающим склоном, выноска уходит за него к вершине. Сколько таких подписей в кадре, решает бюджет: видимые разбирают места первыми, скрытым достаётся остаток (ALGORITHMS.md §2)
- **Навигация**: WASD/стрелки, shift+drag, двойной тап, nav pad крестом (вперёд/назад/влево/вправо + GPS в центре — диагонали убраны как избыточные)
- **Высота**: кнопки ⬆⬇ ±100м, индикатор; набранная высота сохраняется при перемещении, GPS возвращает на землю
- **Настройки**: список регионов с группировкой, размеры, кнопки скачивания
- **Иконки**: инлайновые SVG (`src/ui/icons.ts`) вместо эмодзи — «📷» и «📸» на панораме означали AR и снимок, а различить их было нельзя; шестерёнку из тонких штрихов принимали за солнце, теперь ползунки
- **Карта OSM**: свой slippy-map без библиотек — маркер позиции с сектором взгляда, перетаскивание, зум; «Перенестись сюда» переключает регион по bbox
- **Поиск**: живёт внутри карты (и то и другое — «переместиться в другое место», незачем занимать два угла экрана). Список вариантов с указанием региона; ищет по всей планете через `peaks/_index.json`, а не только в скачанных регионах; «Казбек» находит `Kazbek` (ALGORITHMS.md §6)
- **PWA**: манифест с иконками, установка на домашний экран (`install.html`), Service Worker с версионированием кешей и плашкой «Доступно обновление»
- **Перелёт к вершине**: точка обзора подбирается по DEM (12 азимутов, видна ли вершина), камера сама наводится на рельеф (ALGORITHMS.md §7)
- **AR**: getUserMedia + тот же `drawOverlay()` поверх кадра камеры
- **Фото**: снимок с подписями → Web Share API
- **PWA**: Service Worker, IndexedDB, офлайн-режим

### i18n
- **12 скриптов**: кириллица, грузинский, армянский, греческий, арабский, тибетский, деванагари, тайский, эфиопский, катакана, хангыль, пиньинь
- **Локали**: ru/en, автоопределение

## Известные проблемы

### 1. Подписи пиков висят в воздухе
**Симптом**: маркеры пиков не на силуэте, а выше/ниже.

**Причина**: OSM ele ≠ DEM высота в точке (разные источники).

**Текущий фикс**: `findPeakMarkerPosition` ищет ближайший «горб» на силуэте по азимуту/дистанции. Подпись теперь якорится прямо в этой точке, поэтому расхождение заметнее — требует проверки в поле.

### 2. Vite SPA-fallback trap
**Симптом**: 404 на JSON возвращает index.html с HTTP 200.

**Фикс**: проверять `Content-Type` перед парсингом.

## Решённые проблемы

### Ложные вертикали на контурах склонов (решено)
**Симптом был**: сквозь кадр протягивались крутые вертикальные линии,
не соответствующие никакому рельефу.

**Причина**: полилиния силуэта рвалась при разрыве по горизонтали, но не по
вертикали. Соседние лучи (0.1°) могут попасть на разные поверхности — край
гребня и далёкое дно долины за ним, — и такие точки соединялись отрезком.

**Решение**: разрыв полилинии при скачке угла круче `MAX_RIDGE_SLOPE`
(`buildRidgeSegments` в panorama.ts), тест `test/panorama.test.ts`.

### Вулканы отсутствовали в данных вершин (решено)
**Симптом был**: Эльбрус не подписан на панораме — при том, что стоишь прямо
на нём. В `peaks/elbrus.json` (1589 вершин) обеих вершин Эльбруса не было.

**Причина**: экстракторы брали только `natural=peak`, а вулканы в OSM
размечены тегом `natural=volcano`. Вместе с Эльбрусом терялись Казбек, Фудзи,
Килиманджаро, Демавенд, Ключевская — и смысл целых регионов реестра
(Камчатка, Эквадор, Центральная Америка).

**Решение**: `SUMMIT_TAGS = ("peak", "volcano")` в `tools/planet-peaks`,
такой же union-запрос в `tools/peaks-to-json`; вулканы помечаются
`volcano: true`. Приэльбрусье: 1589 → 1605 вершин, из них 11 вулканов.
Проверено в приложении: «Эльбрус Восточный · 5621 м · 5.3 км» на силуэте.

### Треугольник на своём склоне (решено)
**Симптом был**: стоя на склоне Эльбруса (4127 м), гора рендерилась как монолитный треугольник до края экрана.

**Причина**: заливка слоёв по дистанции. Ближний слой хранил один max-угол на луч, поэтому заливка «от низа экрана до линии» математически обязана была дать треугольник — внутри него не было информации о рельефе.

**Решение** (см. `src/core/horizon.ts`, `src/ui/panorama.ts`):
- Считаем **видимые гребни**: локальные максимумы угла возвышения вдоль луча, после которых угол падает. Только такие точки видны в кадре как линия силуэта — на ровном склоне это одна линия (вершина), а не стопка параллельных.
- Гребни раскладываются по корзинам дистанций (`CREST_BOUNDS`), рисуются от ближних к дальним с окклюзией по running max.
- Рендер — **только контуры**, без заливок: каждый гребень обводится дважды со сдвигом по вертикали (чёрная линия сверху, белая снизу), толщина масштабируется по `devicePixelRatio`. Это даёт контраст при наложении на кадр камеры.
- Полилиния **разрывается** там, где нет данных, а не «примагничивается» к линии горизонта.
- Вертикальный FOV выводится из горизонтального и пропорций холста (был фиксированный 25°, из-за чего проекция была сжата и крутой ближний рельеф уходил за кадр).

### Service Worker не собирался (решено)
**Симптом был**: офлайн-режим и установка PWA не работали ни разу.

**Причина**: приложение регистрировало `sw.js`, но в `dist/` его не было —
`src/sw.ts` не попадал ни в одну сборку. Vite собирает граф от `index.html`,
а worker должен быть отдельным самодостаточным файлом по стабильному адресу.

**Решение**: отдельная сборка `vite.sw.config.ts` → `dist/sw.js` (iife, без
хеша), версия — хеш исходника: браузер считает worker обновившимся только при
побайтовом изменении файла, а имена кешей меняются вместе с ним.

### Панорама исчезала при смене размера окна (решено)
**Симптом был**: поворот телефона — пустой экран до следующего пересчёта.

**Причина**: `resize()` менял `canvas.width/height` (это очищает холст), но
перерисовку не вызывал.

**Решение**: `draw()` в конце `resize()`; объявление `panorama` пришлось
поднять выше — `resize()` выполняется при загрузке модуля и падал на TDZ.

## Архитектура данных

```
Слой 0 (онлайн): AWS Terrarium z9–z15 (весь мир, точнее в ближней зоне)
  ↓ fallback
Слой 1 (офлайн): глобальная пирамида GLO-90 — отдельный репозиторий
  agran/vershiny-dem → Pages, tiles/global/{lod}/{x}/{y}.bin.gz
  (217 м / 435 м / 1.7 км, gzip + дельта; плюс детальные патчи /tiles/{region})
  ↓ fallback
Слой 2 (кеш): IndexedDB (dem-tiles, terrarium, peaks)
```
