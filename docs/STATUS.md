# Текущее состояние проекта (2026-08-12)

## Что работает

### Ядро
- **Ray-marching горизонта**: 3600 лучей, кривизна Земли + рефракция (k=0.13), Web Worker
- **Terrarium DEM**: глобальный онлайн-слой (AWS), z9–z12 по дальности луча
- **Пики**: 522 780 вершин из planet-260803.osm.pbf, 115 регионов, двуязычные названия
- **Проекция**: азимут/возвышение → экран, подписи с кластеризацией

### UI
- **Canvas 2D**: контуры силуэта (двойная линия: чёрная сверху, белая снизу), шкала азимутов, подписи вершин под углом 60° с первой буквой над вершиной
- **Стиль под камеру**: никаких заливок и плашек — только контрастные линии и текст с обводкой, чтобы оверлей совмещался с реальным кадром
- **Навигация**: WASD/стрелки, shift+drag, двойной тап, nav pad (8 направлений + GPS)
- **Высота**: кнопки ⬆⬇ ±100м, индикатор текущей высоты
- **Настройки**: список регионов с группировкой, размеры, кнопки скачивания
- **Поиск**: поиск пиков с fallback на другие регионы
- **AR**: getUserMedia + оверлей панорамы
- **Фото**: снимок с подписями → Web Share API
- **PWA**: Service Worker, IndexedDB, офлайн-режим

### i18n
- **12 скриптов**: кириллица, грузинский, армянский, греческий, арабский, тибетский, деванагари, тайский, эфиопский, катакана, хангыль, пиньинь
- **Локали**: ru/en, автоопределение

## Известные проблемы

### 1. Подписи пиков висят в воздухе
**Симптом**: маркеры пиков не на силуэте, а выше/ниже.

**Причина**: OSM ele ≠ DEM высота в точке (разные источники).

**Текущий фикс**: `findPeakMarkerPosition` ищет ближайший «горб» на силуэте по азимуту/дистанции. Подпись теперь якорится прямо в этой точке, поэтому расхождение заметнее — требует проверки в поле.

### 2. Vite SPA-fallback trap
**Симптом**: 404 на JSON возвращает index.html с HTTP 200.

**Фикс**: проверять `Content-Type` перед парсингом.

## Решённые проблемы

### Треугольник на своём склоне (решено)
**Симптом был**: стоя на склоне Эльбруса (4127 м), гора рендерилась как монолитный треугольник до края экрана.

**Причина**: заливка слоёв по дистанции. Ближний слой хранил один max-угол на луч, поэтому заливка «от низа экрана до линии» математически обязана была дать треугольник — внутри него не было информации о рельефе.

**Решение** (см. `src/core/horizon.ts`, `src/ui/panorama.ts`):
- Считаем **видимые гребни**: локальные максимумы угла возвышения вдоль луча, после которых угол падает. Только такие точки видны в кадре как линия силуэта — на ровном склоне это одна линия (вершина), а не стопка параллельных.
- Гребни раскладываются по корзинам дистанций (`CREST_BOUNDS`), рисуются от ближних к дальним с окклюзией по running max.
- Рендер — **только контуры**, без заливок: каждый гребень обводится дважды со сдвигом по вертикали (чёрная линия сверху, белая снизу), толщина масштабируется по `devicePixelRatio`. Это даёт контраст при наложении на кадр камеры.
- Полилиния **разрывается** там, где нет данных, а не «примагничивается» к линии горизонта.
- Вертикальный FOV выводится из горизонтального и пропорций холста (был фиксированный 25°, из-за чего проекция была сжата и крутой ближний рельеф уходил за кадр).

## Архитектура данных

```
Слой 0 (онлайн): AWS Terrarium z9–z15 (весь мир)
  ↓ fallback
Слой 1 (офлайн): наши int16-патчи /tiles/{region}/{lod}/{x}/{y}.bin
  ↓ fallback
Слой 2 (кеш): IndexedDB (dem-tiles, terrarium, peaks)
```
