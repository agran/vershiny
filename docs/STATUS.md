## Код-ревью и правки 2026-08-20 (docs/CODE-REVIEW-2026-08-20.md)

Исправлены все 5 багов ревью и внедрены все 8 ускорений, отдельными коммитами:

  дальние фронты (маркеры вершин).

  не меняется — тест-инвариант в horizon.test.ts); смена региона грузит пики
  и DEM параллельно; изоляция скачанных регионов на карте — из кеша;
  маркеры пиков кешируются на версию панорамы.
- **Полевой баг 2026-08-20 (Краснодар)**: `observerHeight(Safe)` выбирал
  детальный слой по bbox и бросал «Точка вне покрытия DEM», не пробуя

## Что работает

### Ядро

- **Ray-marching горизонта**: 3600 лучей, кривизна Земли + рефракция (k=0.13), Web Worker
- **Гребни силуэта**: локальные максимумы угла вдоль луча по корзинам дистанций (`CREST_BOUNDS`) — только они реально видны как линия силуэта
- **Terrarium DEM**: глобальный онлайн-слой (AWS), z9–z12 по дальности луча
- **Пики**: 692 355 вершин из planet-260803.osm.pbf (включая 4984 вулкана), 124 региона, двуязычные названия
- **Проекция**: азимут/возвышение → экран, вертикальный FOV выводится из пропорций холста

### UI

- **Canvas 2D**: контуры силуэта (двойная линия: чёрная сверху, белая снизу), шкала азимутов, подписи вершин под углом 60° с первой буквой над вершиной. Части подписи (название, высота, расстояние) скрываются по отдельности: часть, уходящая за край кадра хотя бы на несколько пикселей, пропадает целиком вместе со своим « · », остальные остаются на местах (`labelFullyOnScreen` проверяет рамку глифов в экранных координатах, `visibleLabelRange` режет строку по границам частей). Подпись стремится к минимуму строк и возвращается в одну строку, как только края кадра перестают мешать; вторая строка («высота · расстояние») появляется, когда в одной строке теряются части; скрытые вершины переносятся так же: их подпись поднята над склоном целиком, и нижняя строка на склон не ложится; название, не влезающее в строку, переносится по пробелам и дефисам (дефис остаётся в конце строки) — до трёх фрагментов, каждый виден целиком или скрыт; строки подписи центрируются под первой, у кромок кадра откатываются к левому выравниванию; многострочная подпись якорится нижней строкой: выноска к ней остаётся короткой (стандартный LEAD от вершины) при любом числе строк, остальные строки уходят вверх — пачка целиком выше точки вершины; нижняя строка не сдвигается левее якоря, чтобы не накрыть кружок и стрелку; название, уходящее за край кадра, свешивается (канвас обрежет сам), и многострочность при этом сохраняется; если перенос не помогает (нет точек разрыва или фрагмент всё равно не влезает), полная строка частично уходит за левый и правый край экрана — ничего не скрывается, лишнее обрежет канвас; **выноски не пересекают чужие подписи и чужие выноски** — кандидат с пересекающей выноской отклоняется, а если из-за соседа подпись вынуждена подниматься, допускается **парный сдвиг**: сосед поднимается вместе с ней, когда максимум длин выносок пары уменьшается; **на время перетаскивания панорамы раскладка замораживается** (stableLabels): подписи не перекладываются, а переезжают вместе со своими вершинами — многострочность, обрезка и дорожки не меняются, пересчёт — на первом кадре после жеста; свешиваться за край кадра строке позволено, только если она видна хотя бы краешком (`labelPartiallyOnScreen`) — подпись-невидимка место и бюджет не занимает; выноска скрытой вершины обрывается точно на линии силуэта
- **Стиль под камеру**: никаких заливок и плашек — только контрастные линии и текст с обводкой, чтобы оверлей совмещался с реальным кадром
- **Приоритет подписей**: `ele · (1 + 0.4·exp(−d/40км)) · w(изоляция)` — высота, близость и «интересность» вершины; вытесненная подпись просто не рисуется
- **Изоляция вершин**: расстояние до ближайшей более высокой (заменитель prominence, которого в OSM нет). Из тесной группы подписывается главная, одиноко стоящая гора не проигрывает побочному пику соседнего массива. 49 тыс. вершин — 89 мс (ALGORITHMS.md §5)
- **Скрытые вершины**: вершине не хватило до гребня <400 м — подписывается серой пунктирной выноской без кружка-маркера. Подпись поднимается над загораживающим склоном, выноска уходит за него к вершине. Сколько таких подписей в кадре, решает бюджет: видимые разбирают места первыми, скрытым достаётся остаток (ALGORITHMS.md §2)
- **Навигация зависит от устройства**: на телефоне перемещения наблюдателя нет вовсе — панорама строится из текущей точки GPS, а уйти в другое место можно картой; остаётся кнопка возврата к своему положению и высота ⬆⬇. На компьютере поддержан весь разбор маршрута заранее: WASD/стрелки, shift+drag, двойной клик по склону, навипад крестом (вперёд/назад/влево/вправо + GPS в центре)
- **Поворот экрана**: угол обзора привязан к длинной стороне (70°), короткая получает производный — иначе портретный экран растягивал вертикаль до сотни градусов и те же горы становились вдвое мельче, чем в ландшафте. Кнопки в низком экране выстраиваются в ряд вдоль нижнего края. **Ориентация автоматическая** (`core/screen-orientation.ts`): интерфейс следует за хватом телефона — угол крена из датчика (rollRad, гистерезис: вход в ландшафт за 75°, возврат в портрет под 40°) сам поворачивает кнопки, настройки и карту, включая перехват другим боком на 180° в ландшафте. Кнопка поворота с главного экрана убрана, ручных режимов больше нет. Реализация **чисто программная, БЕЗ обязательного Screen Orientation lock и fullscreen** (lock на Android требует fullscreen, на Samsung отклоняется, на iOS API нет вовсе): document.body поворачивается CSS-трансформом на 90°, система остаётся в портрете, приложение повёрнуто. Где API позволяет, по первому касанию холста пробуем зафиксировать окно в портрете через `screen.orientation.lock()` (`lockSystemOrientation`, без fullscreen): срабатывает в установленном PWA и в браузерах, где lock разрешён вне fullscreen; в обычной вкладке Android Chrome lock отклоняется — там остаётся системный автоповорот. Где API нет — живём одним CSS-поворотом. Манифест ориентацию **НЕ фиксирует** (после HyperOS: принудительный ландшафт убивал установленное приложение при запуске с рабочего стола) — окно следует за системным автоповоротом, ландшафт по хвату даёт CSS-поворот, пока форма окна совпадает с хватом. До первого показания датчика поворот не включается — на десктопе датчика нет, и крутить окно по «портретному» дефолту нельзя. Ограничения CSS-поворота: vh/vw считаются от физического окна (настройки — в cqh, body делается query-контейнером), экранные дельты/точки указателя конвертируются в локальные оси (toLocalDelta/toLocalPoint) в drag панорамы, панорамировании карты, ручке сектора взгляда и двойном клике, safe-area-инсеты переставляются вручную. Конверсия — **обратным поворотом R(−softAngle)**, а не прямым: прямой зеркалил жесты на 180° в ландшафте (подстройка контуров пальцем шла не в ту сторону), — знак проверен на реальной CSS-матрице `rotate(±90°)`. **Направление поворота — по физической стороне хвата**: rotate(90deg) соответствует телефону, повёрнутому вправо, и на хвате влево UI оказывался вверх ногами (и видео, и контуры повёрнуты «не туда»); сторона берётся из screen.orientation.angle, а пока окно портретное — из знака сырых γ датчика (модуль слушает deviceorientation сам, до main доходят только обработанные азимут/наклон/крен). **Перехват другим боком в ландшафте переворачивает UI на 180° сам**: модуль следит за УГЛОМ КРЕНА roll (третья строка матрицы поворота), а не за сырым γ — тот при вертикальном хвате (β≈90°) вырождается и шумит вместе с α, из-за чего обычный наклон вверх-вниз дёргал UI переворотами. Roll от α и β не зависит и устойчив в любой позе. Гистерезис: переключение только в глубокой зоне |roll|>75°, мёртвая зона вокруг вертикали держит прошлую сторону (при прохождении через вертикаль UI не дёргается), плюс дебаунс 600 мс против шума у порога; колбэк зовёт переворот, main пере-применяет режим. Зелёный цвет кнопки — признак запертого режима. Кнопка есть везде, где есть DOM
- **Компас**: направление взгляда считается по полной матрице поворота (α, β, γ), а не по одному α — иначе при повороте телефона в ландшафт панорама уезжала на 90° (в точке β ≈ 90° углы вырождаются). Раскалиброванный магнитометр (iOS отдаёт точность −1 или событие `compassneedscalibration`) не прячется: по центру появляется плашка «поводите телефоном восьмёркой» — молча рисовать по таким показаниям нельзя, человек поверит подписям и уйдёт не туда. **Крен** (телефон держат не ровно — один угол ниже другого): угол поворота мира в кадре считается по третьей строке той же матрицы (`rollRad` в `lookFromDeviceOrientation`, `atan2(−cosβ·sinγ, sinβ)`), сглаживается лёгкой экспонентой (τ = 0.25 с) и доворачивает оверлей AR вокруг центра кадра — контуры лежат на наклонённом кадре камеры, а не на ровном горизонте. Панорама без камеры крен не использует: горизонт остаётся ровным
- **Высота**: кнопки ⬆⬇ ±100м, индикатор; набранная высота сохраняется при перемещении, GPS возвращает на землю
- **Регион под ногами**: после любого перемещения (GPS, шаг, перелёт по поиску, перенос с карты) проверяется, содержит ли активный регион новую точку. Если нет — плашка «Вы в районе X · Переключить». Сам регион не подменяется: молча заменить список вершин хуже, чем спросить. Пока активный регион точку содержит, предложения нет — даже если у соседнего приоритет выше (регионы перекрываются буфером 200 км, менять работающий незачем). На равнине у подножия (Краснодар, Ростов — вне всех bbox) предлагается ближайший район, но не дальше радиуса видимости вершин: из Москвы предлагать нечего. Отказ запоминается до возвращения в свой регион
- **Системный «назад»**: жест или кнопка «назад» закрывает открытый слой — сначала поиск, потом карту, — а не приложение. Каждый слой добавляет запись в историю (`src/ui/overlay-history.ts`); адрес при этом не меняется. Слои держатся стопкой с одним слушателем: `popstate` получают все сразу, и слушатель на каждый слой закрывал бы одним нажатием и поиск, и карту под ним
- **Настройки**: список регионов с группировкой, размеры, кнопки скачивания. Активный регион в строке «Регион» — ссылка: клик проматывает панель до его строки в списке (с вспышкой фона), где его можно скачать или выбрать соседний; при клике до загрузки реестра прокрутка откладывается до построения списка. Строка выбора языка помечена глобусом и подписана сразу на обоих языках («Язык / Language»): её ищет тот, кто попал в чужой язык интерфейса и по определению не прочитает подпись на нём. Вверху — кнопка «Поделиться ссылкой на установку» (`install.html`): на телефоне открывает системный лист «Поделиться», на десктопе копирует ссылку в буфер обмена
- **Иконки**: инлайновые SVG (`src/ui/icons.ts`) вместо эмодзи — «📷» и «📸» на панораме означали AR и снимок, а различить их было нельзя; шестерёнку из тонких штрихов принимали за солнце, теперь ползунки. На время начальной загрузки (пока идут «Загрузка…» → «Расчёт панорамы…») каждая кнопка подписана **выносной плашкой со стрелкой** (`addCaption`/`layoutCaptions` в main.ts): плашка в стороне от кнопки, стрелка указывает на неё — прижатый текст налезал на соседние кнопки и плашки. Авто-разводка сдвигает плашки, пока есть пересечения (друг с другом и с чужими кнопками); непересечение гарантирует `test/captions-layout.test.ts`. С первым результатом воркера (или ошибкой) подписи прячутся. Ради этого все кнопки главного экрана (⚙, AR, фото тоже) создаются в начале `main()`, а не по первому результату воркера; автозапуск камеры по-прежнему ждёт панораму (`arAutoStart` зовётся из обработчика ответа воркера)
- **Карта**: свой slippy-map без библиотек — маркер позиции с сектором взгляда, перетаскивание, зум; «Перенестись сюда» переключает регион по bbox; Escape закрывает. Тайлы — OpenTopoMap: рельеф, вершины с высотами и тропы, подписи на местном языке (в России — кириллица). **Базовый слой вершин — свой, и только офлайн** (`src/ui/map.ts`, `selectMapPeaks`): без сети, когда тайлы OpenTopoMap не приходят вовсе, названия и высоты из нашей базы — единственное содержимое карты, и она не пустеет в горах без связи. Как только тайлы кадра загрузились (и ни один не упал), слой скрывается целиком: на OpenTopoMap вершины уже подписаны, дублировать незачем; сеть пропала посреди работы — слой сам возвращается. Отбор той же формулой значимости, что подписи на панораме (высота · изоляция), а реальный предел задаёт **размещение без перекрытий** (`placeMapPeakLabels`): потолков по счёту нет, свободное место кадра заполняется целиком, и вершина не исчезает из-за вошедших в кадр более значимых соседей (раньше фиксированный «топ-N на зум» вытеснял её даже при пустом экране). Размещение **липкое**: стоявшие в прошлом кадре метки расставляются первыми и держат свой якорь (TTL 30 кадров) — вершина, к которой ведут карту, не гаснет от вошедшей доминанты; при тесноте подпись **уходит на сдвинутый якорь** (правее/левее точки, маркер остаётся на вершине), а не пропадает. Сдвинутая подпись приподнимается на 8 px и соединяется со своим треугольником **выноской** — линией от острия треугольника под угол подписи, заходящей на оба края без зазоров (в плотном поле иначе непонятно, к какому маркеру она относится); коллизионный бокс такой подписи учитывает подъём, чтобы она не наезжала на вершины выше. Ширина подписи — точный `canvas.measureText` с кешем (оценка «6.5 px на символ» завышала бокс в полтора раза и давала ложные столкновения). Переключение слоя по тайлам — с дебаунсом 250 мс и учётом летящих тайлов: раньше при панорамировании въезжающие незагруженные тайлы дёргали весь слой. **Отбор идёт по вершинам в кадре карты, а не по всему региону**: иначе в крупном регионе глобальный топ отдавливал локальные главные вершины (из Краснодара z11 показывал Эльбрус с края bbox «Западного Кавказа», а Фишт-Оштен в кадре не проходил в лимит 24). К текущему региону фоном добавляются вершины всех скачанных офлайн-регионов из IndexedDB
- **Иконки не перехватывают нажатия**: у `<svg>` внутри кнопок `pointer-events:none`. Без этого целью `pointerdown` становится `<path>`, а не кнопка — карта принимала нажатие «Закрыть» за начало перетаскивания, захватывала указатель, и click уходил ей (текстовые «＋»/«−» при этом работали, отсюда «срабатывает через раз»)
- **Сообщения по центру** (расчёт, ошибки, результат совмещения с камерой) — на плашке с размытием фона: светлый текст без подложки пропадал на снежном склоне в кадре камеры, на светлом небе и в гуще подписей вершин
- **Поиск**: живёт внутри карты (и то и другое — «переместиться в другое место», незачем занимать два угла экрана). Список вариантов с указанием региона; скачанный регион ищется целиком, а не по индексу; по всей планете — через `peaks/_index.json`; «Казбек» находит `Kazbek`; если точного совпадения нет, идёт проход с исправлением опечаток («Пшехасу» → Пшехо-Су) (ALGORITHMS.md §6)
- **PWA**: манифест с иконками, установка на домашний экран (`install.html`), Service Worker с версионированием кешей и плашкой «Доступно обновление». Значок, добавленный со страницы установки, открывает саму панораму, а не инструкцию: за это отвечает `start_url` манифеста, и его стережёт `test/manifest.test.ts` — сломать одной строкой легко, а заметить можно только на телефоне. На iOS, открытой в чужом браузере (Chrome, Edge, мессенджер), страница вместо списков инструкций показывает кнопку «Скопировать адрес для Safari» и путь из двух шагов — установить PWA на iOS можно только оттуда
- **Счётчик посещений** (Яндекс.Метрика, `src/core/analytics.ts`): грузится только при живой сети и только в простое — на слабом канале он не соревнуется за полосу с тайлами рельефа, а офлайн не создаёт ни одного запроса. Запуск установленного приложения считается отдельно: с домашнего экрана PWA часто поднимает уже открытый документ, и обычного обращения при загрузке страницы там не происходит — поэтому возвращение на экран после получаса простоя отмечается как новый визит (тот же порог, по которому Метрика сама разделяет визиты). Адрес страницы отправляется без параметров: в ссылке живёт `?lat=&lon=`, и в статистике это было бы координатами конкретного человека. Карта кликов выключена — нужен счёт посещений, а не координаты каждого нажатия. В режиме разработки счётчик не подключается, а в настройках («О проекте») о нём сказано прямо
- **Перелёт к вершине**: точка обзора подбирается по DEM (12 азимутов, видна ли вершина), камера сама наводится на рельеф (ALGORITHMS.md §7)
- **Калибровка**: автосовмещение контуров с кадром камеры (CV по линии «небо / земля», ALGORITHMS.md §3) — само при входе в AR и кнопкой; плюс ручные ползунки (поле зрения камеры, азимут, наклон) в настройках. Поправки сохраняются между запусками. Поле зрения подгоняется и pinch-жестом двумя пальцами прямо на кадре AR — результат виден сразу, без похода в настройки. Линия неба извлекается мультипризнаковым ДП-экстрактором (градиенты яркости/цвета/насыщенности + текстура, приор непрерывности горизонта) с временно́й стабилизацией ~8 кадров — устойчива к закату, дымке, пасмурности, сумеркам, засветке против солнца и облакам над гребнем (синтетическая матрица `test/skyline-weather.test.ts`). **Компас может врать на любой угол, вплоть до разворота**: перед точной доводкой профиль кадра совмещается с горизонтом по полному кругу (круговая ZNCC через БПФ за ~5 мс, `src/core/skyline-match.ts`), а не в окне ±25°; ложные совпадения периодичных гребней отсекаются разрывом с вторым пиком и вершинами-якорями
- **Магнитное склонение — автоматически**: компас отсчитывает азимут от магнитного севера, и раньше эту разницу (+7° на Кавказе, −9° на Камчатке) закрывала ручная подстройка. Теперь склонение добавляется по модели WMM-2025 (`src/core/declination.ts`, коэффициенты из NOAA WMM.COF, проверены по эталону pygeomag) из физического положения GPS; ручной оффсет остаётся только для железа рядом и дешёвых магнитометров
- **Слежение за телефоном — комплементарный фильтр с гироскопом**: азимут интегрируется из `rotationRate` (devicemotion, до 60 Гц — без шума магнитометра и без «резинки» сглаживания при панорамировании), а компас служит только медленным якорем против дрейфа (τ ≈ 1.5 с). Расхождение > 20° принимается сразу, но только после трёх подряд согласных показаний — одиночный выброс магнитометра возле металла картинку не дёргает. Серия из ≥3 таких скачков за 10 с — признак систематического расхождения интеграла с компасом (кривой `rotationRate` на устройстве): гироскоп отключается до конца сессии с диагностикой в консоль (полевой случай: Samsung S25 Ultra дёргал панораму скачком раз в секунду). Если absolute-показания молчат дольше 10 с (компас потерян), снова принимаются относительные — стабильный якорь с постоянным офсетом лучше дрейфа без предела. Там, где `rotationRate` не приходит (десктоп, часть WebView), работает прежняя схема: круговое среднее по окну + слежение с подавлением дрожания. На iOS `DeviceMotionEvent.requestPermission()` запрашивается параллельно с orientation из одного жеста — иначе вторая просьба теряет активацию и гироскоп молча не включается
- **AR (основной режим)**: getUserMedia + тот же `drawOverlay()` поверх кадра камеры. На телефоне включается сам после первого расчёта панорамы (`src/core/ar-mode.ts`); выход из режима и отказ в доступе запоминаются, чтобы диалог о камере не всплывал при каждой загрузке. Оверлей рисуется с FOV **видимой части кадра камеры**: из базового угла калибровки вычитаются зум камеры (`MediaTrackSettings.zoom`, Android Chrome) и cover-кроп видео под экран (`src/core/camera-fov.ts`) — раньше при разных пропорциях экрана и кадра контуры сходились по центру и расходились к краям. В тех же координатах полного кадра работает и автокалибровка. Объект панорамы никогда не подменяется после создания: оверлей захватывает его по ссылке при входе в AR и рисует каждый кадр, поэтому смена региона при активной камере гасит вершины мутацией (`panorama.peaks = []`), а не новой ссылкой — иначе поверх видео навсегда оставались бы подписи прежнего региона (регресс стережёт `test/main-module.test.ts`). Контуры и шкала азимутов рисуются полупрозрачными (сквозь них виден кадр камеры), а подписи вершин — вторым проходом и полностью непрозрачными: полупрозрачный текст на пёстрой картинке камеры выцветает. **Крен телефона** доворачивает оверлей (и снимок из AR) вокруг центра кадра (`rotateAroundCenter` в panorama.ts): если телефон держат с одним углом ниже, кадр камеры уже наклонён, и контуры совмещаются с ним по всему экрану, а не только в центре. В программном ландшафте из крена вычитается softAngle (`overlayRollRad` в core/roll-compensation.ts): крен датчика отсчитывается от портретного окна и при ровном ландшафтном хвате показывает ±90°, хотя довёрнутый кадр стоит ровно — без поправки оверлей лежал боком на 90°. Контуры и шкала при этом рисуются с горизонтальным запасом под поворот (`rollEdgeMarginX`: (W·(1−cosθ) + H·sinθ)/2) — иначе у наклонённого кадра линии обрывались, не дойдя до углов экрана; подписи вершин проверяются на видимость уже в экранных координатах, поэтому не пропадают у краёв повёрнутого кадра. **Кадр камеры при программном повороте UI** (CSS-трансформ body ±90°) доворачивается обратно на −softAngle (`core/frame-orientation.ts`): drawImage CSS-трансформ не применяет, и без доворота картинка лежала на боку. Экран AR, снимок, проба автокалибровки и FOV работают через одни и те же `drawVideoAligned`/`rotatedFrameSize`, чтобы системы координат не разъезжались
- **Фото**: снимок с подписями сохраняется файлом (`vershiny-elbrus-vostochnyy-2026-08-13-225258.png`) — имя по главной вершине в кадре. Время в имени — с секундами, а повтор снимка за одну секунду получает суффикс `-2`, `-3`… (`uniquePhotoFilename`): браузер не спрашивает про уже существующий файл, серия кадров одного места скачивается вся. Подпись в кадре по умолчанию отключена: координаты и время съёмки уезжают вместе с картинкой, а это данные о человеке, а не о горах. В настройках (раздел «Снимок») включаются по отдельности «Место съёмки» и «Дата и время». Место подписывается по той же логике, что имя файла: главной вершиной в кадре («Эльбрус Западный»), а когда видимых вершин нет — названием региона на языке интерфейса («Приэльбрусье»), а не его ключом из реестра («elbrus»); в имени файла и то и другое транслитерируется. Что нарисовано — рисуется обводкой без плашек, на одной нижней строке с адресом сайта; в портретном кадре длинная строка переносится, а не уходит за край. **Контуры склонов на снимке из AR по умолчанию выключены** (галочка «Контуры склонов» там же): кадр содержит настоящие горы, и нарисованный силуэт расходится с ними на величину неточности DEM и калибровки — на фото остаются только подписи вершин. Оверлей на снимке всегда рисуется непрозрачно, даже поверх запечённого кадра камеры: полупрозрачные (как на экране AR) подписи на готовом фото выглядели выцветшими. Снимок без камеры (чистая панорама) рисует контуры при любом положении переключателя — там конфликтовать не с чем
- **Офлайн**: кнопка скачивания показывает состояние текущего региона — стрелка на синем, пока его нет на устройстве, галочка на зелёном, когда есть. Иначе не понять, скачано ли: панорама рисуется в обоих случаях, разница вылезает только в горах без связи. Реестр регионов кешируется в IndexedDB — без сети список в настройках остаётся на месте, и активный регион можно сменить
- **Старт без ожидания спутников**: положение берётся в два этапа. Сначала быстрое — готовый фикс системы (принимается, если ему меньше пяти минут) или точка прошлого запуска; панорама считается сразу. Настоящее положение подставляется, когда спутники ответят, и только если человек оказался дальше 500 м от показанного. Без сети недоступен A-GPS, и холодный фикс занимает десятки секунд: раньше всё это время висела заставка «Определяем положение по спутникам…». Ожидание осталось только там, где показать нечего — на самом первом запуске. Отладочный вход `?lat=&lon=` резолвится мгновенно. Запасная точка (Приют 11) и точка прошлого запуска помечены как недостоверные: по ним не подбирается регион и не предлагается соседний — иначе человек, которому не дали геолокацию, получал бы «Вы в районе Приэльбрусья», где бы он ни находился. Кнопка «К моему положению» при отказе честно говорит об этом вместо переноса на Приют 11 (`src/core/position.ts`)

## Известные проблемы

### 1. Подписи пиков висят в воздухе

**Симптом**: маркеры пиков не на силуэте, а выше/ниже.

**Причина**: OSM ele ≠ DEM высота в точке (разные источники).

**Текущий фикс**: `findPeakMarkerPosition` ищет ближайший «горб» на силуэте по азимуту/дистанции. Подпись теперь якорится прямо в этой точке, поэтому расхождение заметнее — требует проверки в поле.

### 2. Vite SPA-fallback trap

**Симптом**: 404 на JSON возвращает index.html с HTTP 200.

**Фикс**: проверять `Content-Type` перед парсингом.

### 3. Вершины без `ele` не подписываются

**Симптом**: гора видна, но безымянна, хотя есть в данных.

**Причина**: `checkPeakVisibility` отбрасывает вершину без высоты, а взять её из DEM (как обещает комментарий в `peaks.ts`) пока некому. В OSM `ele` заполнен не везде.

### 4. Кеш тайлов в памяти не ограничен

**Симптом**: длинная сессия с перемещениями по планете растит потребление памяти без предела (Terrarium — 262 КБ на тайл).

**Причина**: `tiles` в `TerrariumSampler`/`DemSampler` только растёт. Вытеснение придётся делать аккуратно: выбросить тайл, нужный идущему расчёту, — значит получить дыру в панораме.

### 5. Экстрактор силуэта: этап 1 внедрён, ждёт полевых испытаний

**Было**: поколоночный порог Оцу по «0.6·яркость + 0.4·синева» — работал только в ясный день.

**Сделано** (план `docs/SKYLINE-EXTRACT-NEXT.md`, подходы A и C): мультипризнаковая карта кандидатов (градиенты яркости/цвета/насыщенности + скачок текстуры), фильтры «импульс/ступенька», «самая верхняя значимая граница», «небо сверху», выбор линии ДП с состоянием NONE и платным возобновлением; временна́я стабилизация ~8 кадров с выравниванием кросс-корреляцией (облако над гребнем уходит в NaN по временно́й дисперсии). Устойчивость подтверждена синтетической матрицей `test/skyline-weather.test.ts` (7 погод × 3 рельефа, медиана ошибки ≤ 0.5 строки сетки во всех режимах).

**Осталось**: полевые испытания на реальной камере (синтетика не воспроизводит блики линзы, шлейфы автоэкспозиции и настоящий лес); этап 2 — guided search по форме DEM после первого совмещения (см. план, защита от циркулярности там же).

### 6. Крен и ориентация: остатки полевых проверок

**Сделано**: оверлей AR доворачивается на видимый крен (rollRad минус softAngle в программном ландшафте, `overlayRollRad`) вокруг центра кадра — при заваленном на угол телефоне контуры совпадают с кадром камеры. **Компенсация крена включена всегда** — настройка из раздела «Компенсация крена» убрана (`core/roll-compensation.ts` оставил только `overlayRollRad`). **Кадр камеры при программном повороте UI** доворачивается на −softAngle (`core/frame-orientation.ts`): экран AR, снимок и проба автокалибровки рисуют через одни и те же `drawVideoAligned`/`rotatedFrameSize`, чтобы системы координат не разъезжались. **Ландшафтное окно**: кадр под окно довернул уже браузер, и `overlayRollRad` вычитает угол окна (screen.orientation.angle) при ландшафтном хвате — Android Chrome отдаёт события в координатах устройства, где ровный ландшафтный хват выглядит как крен ±90°.

**Осталось**:
- **Проверить на iOS**: deviceorientation на iOS компенсирован под окно, а не под устройство — в программном ландшафте крен датчика может быть ≈0, и знак `overlayRollRad`/определение стороны хвата по roll потребуют платформенной ветки.
- **Автокалибровка** (skyline) снимает кадр без учёта крена: на заваленном телефоне линия «небо/земля» в кадре наклонена, и совмещение по ровной модели деградирует. Нужен доворот пробы на −roll.

## Решённые проблемы

### Компас на iOS: доступ ждал невзрачной кнопки на каждом запуске (решено, 2026-08-21)

Полевой баг (iPhone, установленный PWA): после каждого запуска программа
не следила за положением телефона, пока не нажмёшь маленькую кнопку
«Включить компас» — только её обработчик вызывал
`requestPermission()` из жеста. Теперь доступ запрашивается при ПЕРВОМ
касании в любом месте (`hookFirstGesture` в orientation.ts: capture +
once — проведение по панораме, любая кнопка, настройки — всё считается
жестом), и искать иконку не нужно. Повторный отказ диалогом не спамим:
хук одноразовый, кнопка остаётся ручным повтором. Пока доступ не дан,
кнопка компаса пульсирует акцентным цветом — её видно. Если iOS не
запомнила грант (поведение Web.app), диалог появится один раз за запуск,
в момент первого касания — а не как ритуал поиска кнопки.

### PWA убивалось при запуске на Xiaomi HyperOS (решено, 2026-08-21)

Полевой баг: установленное из Chrome приложение на HyperOS 3.0 не
запускалось — иконка камеры вспыхивала на долю секунды, и процесс
исчезал без единого события JS (обработать «падение» в коде нельзя).
Причина — автозапуск камеры во время старта установленного PWA: на
этой прошивке он убивает процесс (в табе Chrome то же самое работало).
Решение в три слоя:
1. **Камера по умолчанию включена** — и во вкладке, и в установленном
   приложении на первом запуске (главный режим). Исключения: Mi Browser
   и запомненный отказ «off».
2. **Сторож автозапуска**: перед автозапуском в standalone ставится
   метка в localStorage, снимается при любом ответе камеры (или при
   успешном ручном включении). Если следующая загрузка видит метку —
   прошлый автозапуск убил сеанс, и эта загрузка идёт без камеры, пока
   человек не включит её кнопкой. Самоисцеление на любых прошивках, где
   старт камеры на запуске фатален.
3. **Mi Browser**: установленное из него приложение камеру не открывает
   вовсе (сломан getUserMedia) — автозапуск отключён, кнопка объясняет
   «откройте в Chrome» (`isMiBrowser` по UA).

Повторное поле (тот же день): после отключения автозапуска камеры
приложение всё равно не запускалось с рабочего стола, а из уведомления

принудительным поворотом окна из лаунчера. Ориентация из манифеста

### Обрезанные подписи у краёв кадра (решено, 2026-08-19)

Подпись ставилась, если видна хоть её часть: при повороте она «выезжала»
из-за края кадра, и канвас обрезал то начало названия, то высоту, то хвост
«· 12 км» — обрезок текста читался как брак. Теперь `labelFullyOnScreen`
проверяет, помещается ли отрезок строки (рамка глифов: ± полувысота с
обводкой) в кадр в экранных координатах (с учётом доворота кадра на крен),
а `visibleLabelRange` режет строку по границам частей: часть, уходящая за
край хотя бы на несколько пикселей, пропадает целиком вместе со своим
« · », остальные остаются на своих местах — сперва отпадает хвост «· N км»,
затем «· высота», название держится, пока влезает само. Если не влезла ни
одна часть, подпись не ставится вовсе (вместе с точкой на вершине). Тут же
появилась **двустрочная форма**: когда под подписью есть свободное место
(вторая строка помещается в кадр и её дорожка не занята соседями), название
остаётся первой строкой, а «высота · расстояние» переезжают на вторую, под
первой — длинная строка не растягивается по кадру. Раскладка строится
на лету из кандидатов по критерию
«полнота названия > число видимых частей высоты/расстояния > меньше строк»:
одна строка → две строки → перенос названия по пробелам и дефисам на 2–3
фрагмента (дефис остаётся в конце строки), info-строка — последней, если
для неё есть место; скрытые вершины переносятся так же — их подпись
поднята над склоном целиком, и нижняя строка на склон не ложится. Подпись **стремится к минимуму строк**: как только
полная строка вновь помещается в кадр (поворот телефона, панорамирование),
она возвращается в одну строку. Многострочная подпись **якорится нижней
строкой**: та стоит на обычном LEAD от вершины, выноска остаётся короткой
при любом числе строк, а остальные строки уходят от неё вверх — пачка
целиком выше точки вершины, а не на склоне. Точки
разрывов и ширины фрагментов токенизируются один раз и кешируются
(`nameTokens`, `MAX_LABEL_LINES`/`MAX_NAME_BREAKS` — потолки строк и
разрывов). Строки центрируются под первой: сдвиг вдоль оси текста на
(w₀−wₖ)/2 с округлением до целых пикселей (иначе субпиксельное дрожание
ширин из кеша мерцало бы между кадрами). Сдвиг считается после обрезки,
но до проверок: сдвинутая строка перепроверяется на кадр и свою дорожку,
при неудаче детерминированно откатывается к левому выравниванию. Нижняя
строка (якорь выноски) не сдвигается левее якоря — иначе текст накрыл бы
кружок вершины и стрелку. Уходящее за край кадра название свешивается:
кандидат B (название + info-строка) не проваливается, а рисует название
целиком, и канвас обрезает лишнее — подпись не схлопывается в одну строку.
Если
перенос не помогает, ставится **полная строка, частично уходящая за левый
и правый край** (канвас обрежет сам): штраф в критерии держит её ниже всех
влезающих раскладок, но выше тех, что что-нибудь скрывают — части подписи
никогда не теряются бесследно.

### Выноски пересекали чужие подписи и выноски (решено, 2026-08-19)

В плотном кластере стрелка поднятой подписи проходила сквозь соседний
текст, а стрелки соседних вершин — друг через друга. Теперь кандидат
отклоняется целиком, если его выноска (отрезок от точки вершины до первой
буквы нижней строки, у скрытой вершины — только видимая часть, обрезанная
силуэтом) пересекает рамку чужой строки или чужую выноску; проверяется и
обратное — чужая выноска не должна проходить сквозь рамки кандидата
(`leaderCrossesBox` переводит отрезок в повёрнутые координаты (u, v) и
делает slab-тест против рамки глифов, `segmentsCross` — строгое
пересечение отрезков). Чтобы теснота не съедала подписи, появился
**парный сдвиг**: если сосед мешает (дорожкой или выноской), его подпись
можно поднять на 1–3 дорожки вверх — подъём допустим, только если все её
строки остаются в кадре целиком и никого не пересекают, — и пересчитать
раскладку нашей подписи против сдвинутого соседа. Обмен принимается, когда
максимум длин выносок пары уменьшается; когда места не нашлось вовсе,
подъём соседа может его открыть. Инвариант «выноски не пересекают чужие
подписи и друг друга» в плотном кластере стережёт тест в
test/panorama.test.ts (8 вершин вплотную, геометрия проверяется по
записанным fillText/сегментам). Кандидаты на парный сдвиг отбираются не по
пересечениям с уже ПОДНЯТЫМ вариантом, а по естественным дорожкам 0…−2
полной строки — иначе поднятая подпись «теряла» виновника, и улучшить её
было нельзя. Второй способ размена — сдвиг соседа **вправо вдоль его
строки** (до 120 px, с потолком и половинным вариантом): его выноска
растёт по горизонтали, наша подпись получает возможность спуститься,
и критерий «меньше максимум длин выносок пары» выбирает между подъёмом
и сдвигом дешевле; равные выноски пары — частый оптимум.

### Подпись-невидимка и повисшие выноски (решено, 2026-08-19)

Фолбэк D («ничего не скрываем, канвас обрежет») ставил подпись и тогда,
когда в кадре не видно ни одной буквы: невидимая подпись занимала дорожки
и бюджет скрытых вершин, выталкивая видимые подписи. Теперь свешивание

### Подписи схлопывались в одну строку во время перетаскивания (решено, 2026-08-19)

Во время жеста кадры идут из кеша сцены, а при его перерисовке подписи
перекладывались под **расширенный** FOV кеша (шире экранного на поля
запаса) — в широком кадре всё помещалось в одну строку, и многострочные

рендере, и в кеше сцены): `labelLayoutCache` хранит последнюю раскладку

### Плашка «Доступно обновление» после уже свежей версии (решено, 2026-08-19)

Оболочка отдаётся network-first, поэтому при запуске после выхода
обновления страница сразу загружается НОВОЙ версией, а новый SW в это же
время встаёт в waiting — и плашка предлагала обновление к уже актуальному
приложению. Теперь плашка ждёт вердикта проверки свежести
(`pageIsCurrent` в src/ui/update.ts): хеш Vite из имени собственного
главного чанка сравнивается с чанком из index.html, который сервер отдаёт
сейчас (обычный fetch проходит мимо SW-стратегий — всегда сеть; офлайн —
страница считается старой, поведение прежнее). Вердикт пересчитывается на
каждой установке нового SW: обновление, вышедшее посреди сессии, плашку
возвращает. Сценарии (гонка холодного старта, свежая страница +
updatefound, обновление посреди сессии) — в test/update.test.ts.

### Подпись «Карта» ложилась на свою кнопку при загрузке (решено, 2026-08-19)

У запертой кнопки (карта в левом нижнем углу, слева край экрана, кругом

### Ландшафт на телефоне: контуры лежали на боку из-за крена (решено, 2026-08-19)

Вторая половина того же симптома (после правки двойного поворота ниже).
На S25 Ultra в ландшафтном окне (`landscape-primary 90°`) события
`deviceorientation` идут в координатах УСТРОЙСТВА: при ровном ландшафтном
хвате β≈0, γ≈−85, и крен датчика ≈ +98° — а кадр камеры браузер уже
довернул под окно, так что картинка ровная. `overlayRollRad` вычитал
только softAngle (0 в ландшафтном окне) и доворачивал оверлей на ~90°:
контуры и подписи вставали вертикальным столбом поверх ровного видео.
Теперь при ландшафтном хвате в ландшафтном окне вычитается ещё и угол
окна (90° у landscape-primary, −90° у secondary): видимый крен = крен
датчика − угол окна (98 − 90 = 8° на живом устройстве). На iOS события
в координатах экрана (крен ≈ 0, форма хвата портретная) — коррекция не
включается. Данные с телефона: portrait β=83 γ=1; landscape β≈−8 γ≈−85.

При вращении телефона из ландшафта в портрет коррекция сперва
отключалась на середине дуги: форма хвата по гистерезису переключалась
в «портрет» при |roll| < 40°, хотя окно ещё ландшафтное, и оверлей
прыгал на 90° — до системной смены ориентации, после которой всё
выправлялось. Теперь систему координат датчика (устройство/экран)
отслеживает защёлка `deviceReferencedEvents()` в screen-orientation.ts:
она ставится при |roll| > 45° в ландшафтном окне и снимается только с
выходом окна из ландшафта — коррекция держится на всей дуге вращения.

### Ландшафт на телефоне: контуры поворачивались на 90° (решено, 2026-08-19)

В ландшафтном окне (системный автоповорот вкладки, манифест PWA
`orientation: landscape`) приложение включало программный поворот body
ПОВЕР системного ландшафта. Причина: Android Chrome пересчитывает β/γ
`deviceorientation` в координаты ЭКРАНА — при ландшафтном хвате датчик
«выглядит портретным» (roll ≈ 0), и старый признак
`effectiveOrientation() !== tiltForm` решал, что окно и хват не совпали.
Канвас становился портретным, контуры рисовались поперёк и после поворота
body ложились на экран боком; видео (кадр доворачивается на −softAngle) и
кнопки (раскладка по `virtualViewport`) при этом выглядели правильно —
поэтому симптом выглядел именно как «повёрнуты только контуры».
Исправлено в `syncOrientation()`: программный поворот включается ТОЛЬКО
из портретного окна (портретное окно + ландшафтный хват), ландшафтное
окно не доворачивается ни при каком датчике. Воспроизведено в браузере
эмуляцией (ландшафтное окно + синтетические β/γ + поддельный поток
камеры). Заодно `drawArOverlayCached` не падает на нулевом размере
холста — `drawImage` с нулевым буфером бросал InvalidStateError и гасил
rAF-цикл AR до перезапуска.

### Моргание оверлея при повороте и резкие перескоки кнопок (решено, 2026-08-19)

Смена размеров холста очищает его, а в AR кадр рисует только rAF-цикл:
между `resize()` и ближайшим тиком оверлей был прозрачным, и контуры
однокадрово мигали поверх видео при повороте телефона. У сессии AR
появился `redraw()` (оба слоя немедленно), и `resize()` вызывает его
вместо `draw()`. Заодно кнопки больше не телепортируются: поворот body
(программный ландшафт) анимируется (`transition: transform 0.22s`), а
кнопки, навипад, панель высоты и плашки подписей получили короткие
переходы left/right/top/bottom (0.15 с) — при переразметке они плывут
на новое место.

### Офлайн-вершины не скрывались поверх загрузившейся карты (решено, 2026-08-18)

Когда в переключение слоя вершин на карте добавили дебаунс (тайлы
догружаются рывками, и слой мигал при каждом запоздавшем тайле), из
`updatePeaksLayerNeed` выпало само присваивание: флаг `peaksLayerNeeded`
навсегда оставался `true`, а таймер каждые 250 мс лишь перепланировал сам
себя. Метки вершин висели поверх OpenTopoMap, где вершины уже подписаны.

Исправлено: подсчёт состояния тайлов вынесен в `computePeaksLayerNeeded()`,
а по таймауту дебаунса состояние пересчитывается на свежем и, если не
вернулось к прежнему, флаг переключается с перерисовкой — в обе стороны:
слой возвращается и при панорамировании на ещё летящие тайлы. Тесты:
`test/map.test.ts`, describe «слой вершин и тайлы».

### Пересборка пирамиды ломала уже скачанный офлайн (решено, 2026-08-18)

Тайлы пирамиды хранятся в IndexedDB сжатыми, а квант высоты подставляется из
index.json при распаковке. Пересборка 2026-08-18 (квант LOD 0: 2 м → 4 м)
сменила байты по тем же URL — старые офлайн-тайлы с новым индексом дали бы
высоты ×2, причём молча. Дополнительный канал протухания — cache-first кеш
тайлов в Service Worker: повторное скачивание после чистки втащило бы старые
байты обратно.

Решение — версионирование содержимого пирамиды:

- `indexVersion(index)` — слепок `cellDeg:quantM:avgTileBytes:tilesX×tilesY`
  по всем LOD, отдельного поля в формате не потребовалось;
- `DemSampler.loadIndex()` при свежем индексе сверяет версию с сохранённой
  (`dem-version:{prefix}` в meta); несовпадение → `deleteDemTilesByPrefix`
  (у глобальной пирамиды префикс пустой — чистятся только ключи «lod/x/y»,
  hi-слой и патчи не трогаем) + отметка `dem-purged:{prefix}`. Наследие без
  версии отличается по кешированному прошлому index.json: совпал — тайлы
  совместимы, чистки нет (hi-слой этим спасается от ложной чистки);
- офлайн-ветка ничего не чистит: старый кешированный индекс согласован со
  старыми тайлами, до первого онлайна они продолжают работать;
- адрес тайла теперь несёт `?v=<версия>`: старый SW такой URL под паттерн
  тайла (якорь `$`) не подхватывает — сеть напрямую; TILE_CACHE бампнут до
  v2, паттерн нового SW query допускает;
- регион в метаданных запоминает `demVersion` на момент скачивания;
  `isRegionOutdated()` = версия не совпала, либо legacy-регион после чистки.

Уведомление пользователя: кнопка скачанного региона в настройках →
«Обновить» (красноватая, title «Рельеф пересобран и стал точнее»), главная
кнопка скачивания меняет цвет, плюс одноразовый тост при старте. Офлайн
приложение честно молчит — без сети проверить свежесть невозможно, а ложная
тревога хуже отложенной.

### Офлайн-слой карты терял вершины (решено)

Три дефекта в дедупликации подписей базового слоя (`src/ui/map.ts`):

- **одноимённые дедуплицировались после лимита** — пачка «Пик №3» съедала
  квоту подписей зума, и на экране оставалось меньше меток, чем позволял
  лимит: соседние вершины не подставлялись;
- **из одноимённых выкидывалась главная** — обход в `renderPeaks` идёт с
  хвоста (от наименее значимых) ради z-order, и в набор `shown` первым
  попадал слабый однофамилец, а доминанта получала `continue`;
- **безымянные вершины схлопывались в одну метку** — `peakName` даёт им
  заглушку `—`, и все такие вершины кадра дедуплицировались друг в друга
  (в OSM имя есть далеко не у всех `natural=peak`).

Исправлено: дедупликация переехала в `selectMapPeaks` и выполняется до
лимита по уже отсортированному списку (выживает главная из одноимённых,
квота добирается соседями), безымянные и `—` не дедуплицируются вовсе.
Вдогонку: состояние «тайл упал» хранится в `dataset.failed`, а не в
`style.visibility`, и `projectPeaks` больше не зовёт `project()` дважды
на вершину. Тесты: `test/map-peaks.test.ts`.

### iPhone зависал на плашке «Загрузка…» (решено)

На iOS Safari страница навсегда оставалась на статичной плашке «Загрузка…»:
модуль приложения не выполнялся. Две причины, по возрастанию версии iOS:

- **бандл собирался под ES2022** — class fields, `??=`, `?.`, числовые
  разделители не парсились Safari < 14.5, и ни одна строка кода не
  выполнялась;
- **горизонт считался в module worker** (`new Worker(..., {type:"module"})`) —
  module workers появились только в Safari 15, раньше вызов бросал исключение
  прямо при загрузке модуля.

Исправлено: `build.target` снижен до `es2019`, воркер собирается классическим
(iife, с инлайном `import('./db')`), а `ResizeObserver` (нет в iOS < 13.4)
обзавёлся фолбэком на `window.resize` в `main.ts` и `map.ts`.

Вдогонку закрыта и совместимость с iOS ≤ 16.3: там в воркере нет
`OffscreenCanvas`/`createImageBitmap` (декодирование Terrarium PNG) и
`DecompressionStream` (распаковка тайлов пирамиды). Добавлены чистые
JS-фолбэки — распаковка DEFLATE (zlib/gzip) через библиотеку `fflate` и
декодер PNG 8-бит RGB/RGBA (`src/core/png.ts`). Включаются только при
отсутствии нативных API, поэтому свежие браузеры идут прежним путём без
изменений. Тест: `test/png.test.ts`.

### iPhone снова висел на «Загрузка…» — temporal dead zone (решено)

После исправления ES2022 и module worker плашка «Загрузка…» оставалась на
iPhone (Safari, где `DeviceOrientationEvent.requestPermission` есть):
`orientationTracker.start()` на iOS вызывает callback синхронно при загрузке
модуля, тот создаёт кнопку «Включить компас», а `setTitle` пишет в
`localizedTitles`. Константа была объявлена ниже по файлу, и первое обращение
попадало в temporal dead zone — `ReferenceError: Cannot access uninitialized
variable`, модуль не выполнялся. На Android/десктопе callback при старте не
вызывается, поэтому баг был виден только на iPhone. Константа перенесена до
`orientationTracker.start()` (`src/main.ts`); тест `test/main-module.test.ts`
импортирует модуль с заглушкой iOS-пути и проверяет, что кнопка компаса
создаётся без исключения.

### Старый Android Chrome падал при старте и не грузил рельеф (решено)

На старых прошивках Android (Chrome < 71–85) проявлялись три «тихих» краша:

- `screen.orientation.addEventListener` отсутствовал до Chrome 59 — вызов
  бросал TypeError при загрузке модуля, страница висела на «Загрузка…».
  Теперь проверяется сам метод, запасной путь — `window.orientationchange`
  (`src/main.ts`);
- `globalThis` появился только в Chrome 71 — `fetch.bind(globalThis)` и
  `globalThis.indexedDB` в сэмплерах DEM/поиске роняли загрузку рельефа.
  Введён `src/core/globals.ts` с фолбэком на `self`;
- `String.replaceAll` нет в Chrome < 85 — русская транслитерация латинских
  названий падала с TypeError. Заменено на `split().join()`
  (`src/core/transliterate.ts`).

### «Закрыть» поиск на карте закрывало и саму карту (решено)

При закрытии вложенного слоя поиска (Escape в поле ввода, выбор вершины из
списка, повторное нажатие кнопки поиска) `release()` слоя вызывал
`history.back()`, а общий слушатель `popstate` снимал следующий слой стопки —
саму карту. Выбор вершины мгновенно закрывал карту вместо показа подобранной
точки обзора. Теперь `popstate`, порождённый собственным `history.back()`,
гасится счётчиком `pendingBacks` (`src/ui/overlay-history.ts`); тест
`test/overlay-history.test.ts` («программное закрытие верхнего слоя не
закрывает слой под ним»).

### Консоль забивалась ошибками Service Worker (решено)

При каждой загрузке страницы в консоль сыпалось «Failed to execute 'clone' on
'Response': Response body is already used» — десятками, по ошибке на ассет.
Стратегия stale-while-revalidate отдавала ответ из кеша странице, а отказ
фонового обновления ловила через `cached.clone()` — к тому моменту тело этого
ответа страница уже прочитала, и клонирование падало само. Заодно вскрылось,
что фоновый запрос никто не удерживал: браузер вправе оборвать запрос, которого
никто не ждёт, и кеш ассетов мог не обновиться вовсе. Теперь обновление живёт
под `waitUntil`, а отказ гасится там же; тест `test/sw.test.ts`.

### Рельеф пропадал за антимеридианом (решено)

У наблюдателя рядом с ±180° (реестр: Врангель `177.5…−177.5`, Новая Зеландия,
Антарктида) лучи уходили за антимеридиан, и оба источника высот молчали разом:
`destination` продолжала счёт за 180° (−180.84°), `lonLatToTile` зажимала такой
индекс в нулевой тайл — с другого края планеты, — а `lonLatToPixel` отдавала
отрицательный пиксель; глобальная пирамида отсекала точку по `gx < 0`. Сектор
панорамы оставался пустым. Долгота нормализуется там, где рождается
(`normalizeLon` в `geo.ts`), индекс тайла заворачивается, а `detailTileKeys`
разворачивает диапазон явно — иначе нормализация обнулила бы детальную зону
Врангеля. Тесты `test/geo.test.ts`, `test/terrarium.test.ts`.

### Касания стрелок не считались коллизией (решено)

`segSeg` обещал в комментарии «включая касание», но неравенства были
строгими: T-образные касания, общие концы и коллинеарные перекрытия
стрелок/плашок не засчитывались, и раскладка могла оставить точно
касающиеся элементы. Добавлена проверка onSegment. Тесты
`test/captions-layout.test.ts`.

### Шов ±180° в высоте точки по Terrarium (решено)

`heightAt` подгружал соседние тайлы для интерполяции, но правый сосед
крайнего тайла мира (x = n−1) отсекался условием `x + 1 < n`. На шве
±180° интерполяция откатывалась на краевой пиксель — сдвиг до ячейки
сетки в последних ~1,5 пикселях тайла. Теперь сосед заворачивается
(`(x + 1) % n`, как в `prefetchAround`). Тест `test/terrarium.test.ts`.

### Worker считал устаревшие панорамы при drag'е (решено)

`requestCompute` слал пересчёт почти на каждый `pointermove` (перемещение
Shift+drag'ом), а worker обрабатывал все сообщения подряд: очередь росла
быстрее расчёта, каждый устаревший compute тратил CPU и prefetch-запросы,
и main всё равно отбрасывал его ответ по `reqId`. В worker теперь явная
очередь заданий (`jobQueue` + `pump`): свежий compute вытесняет ещё не
начатые, ответ приходит только на актуальный запрос.

### Гонка при быстрой смене региона (решено)

`switchRegion(A)` → `switchRegion(B)` без ожидания завершались в обратном
порядке: поздний ответ A перетирал `currentPeaks` уже выбранного B, а его
`initDemForRegion` переключал worker обратно на патч A — панорама и подписи
оказывались от разных регионов. Теперь у смены есть токен актуальности
(`regionSwitchSeq`): устаревший результат отбрасывается до применения.

### DemSource не подхватывал патч за антимеридианом (решено)

`DemSource.inBBox` сравнивал долготу наивно (`minLon <= lon <= maxLon`), хотя
`ui/download.ts:inBBox` антимеридиан учитывал. Для Врангеля
(`177.5…−177.5`) ни одна точка не считалась «внутри bbox» — детальный патч
и hi-слой вокруг него не использовались бы никогда. Логика вынесена в общий
`bboxContains` (`core/geo.ts`), обе проверки делегируют ему. Тест
`test/geo.test.ts`.

### «Закрыть» на карте работало как «Применить» (решено)

Крестик и Escape переносили наблюдателя в центр перекрестия: обработчик
`onclick = close` получал первым аргументом `MouseEvent`, а тот попадал в
параметр `commit` и оказывался истинным. Отказ от карты уносил человека с его
места. Теперь переносит только «Применить», а фабрика кнопок вызывает
обработчик без аргументов. Тесты `test/map.test.ts`.

### Ближняя зона считалась по грубым данным (решено)

Веер предзагрузки (5°, шаг 8 км) ближние километры не покрывал: там все 3600
лучей лежат в одном-двух тайлах, и на зум 12 приходился ровно один. Замер по
пяти точкам: 33–65% выборок ближе 2 км спрашивали незагруженный тайл, и
передний план молча считался по пирамиде 217 м вместо Terrarium 90 м.
`DemSource.prefetchNear` берёт окрестность 3×3 на ближних зумах: промах в
ближней зоне — 0.0%, по всему лучу 1.9–6.0% → 0.2–1.3%, ценой +15% тайлов.

### Один сбой ронял воркер до перезагрузки (решено)

Отклонённый промис `init` оставался в переменной, и каждый следующий расчёт
падал на нём же — с технической формулировкой вместо панорамы, хотя Terrarium
работал. Теперь недоступный патч означает работу по Terrarium, а расчёт держит
свою ссылку на источник: смена региона посреди расчёта больше не подменяет
данные под ним. Той же болезнью болел кеш пирамиды в `download.ts`.

### Загрузка региона отчитывалась об успехе, ничего не сохранив (решено)

`loadTile` любой отказ превращает в `null` — это верно для расчёта панорамы
(«сейчас нет данных»), но счётчик офлайн-загрузки считал успехом и 503 от
офлайнового Service Worker'а. Детальная зона «скачивалась» целиком, регион
помечался готовым, а в горах оказывался пуст. Добавлен
`TerrariumSampler.saveTileOffline` с честным ответом `saved | missing | failed`
(и без лишнего декодирования PNG при массовой загрузке).

### Тайлы разных источников делили ключи в IndexedDB (решено)

Ключ `lod/x/y` одинаков у детального патча региона и глобальной пирамиды, а
сетки у них разные: в общем хранилище они читали бы тайлы друг друга, отдавая
высоты не того места и без признаков ошибки. Теперь у источника своё
пространство имён (`demStorePrefix`); у пирамиды префикс пустой — смена её
ключей обнулила бы уже скачанное на устройствах.

### Рост глаз считался дважды (решено)

`observerHeightSafe` добавляла 2 м, ray-marching — ещё 1.7 м: наблюдатель
стоял на 3.7 м над склоном, а индикатор высоты показывал на два метра больше
отметки под ногами. Прибавка осталась в одном месте (`OBSERVER_EYE_M`).

### Подписи строились по слою 0–5 км, а не по видимой линии (решено)

`horizonAtAzimuth` смотрела в `state.horizon` — ближнюю корзину, которая в
горах почти целиком `−Infinity` (за неё отвечает трава под ногами), и пустые
лучи подменялись нулём. Выноска скрытой вершины обрывалась в воздухе, подпись
«поднималась над склоном», которого в этом расчёте не было. Введена
`silhouetteProfile` — та же линия, что нарисована на экране; ею же теперь
пользуется автокалибровка, чтобы совмещать кадр ровно с видимым силуэтом.

### Прочее из этого же захода (решено)

- офлайн-открытие ссылки с координатами (`?lat=&lon=`) упиралось в 503: в кеше
  оболочка лежит без параметров, добавлен явный откат на неё;
- камера продолжала гореть, если `play()` отклонялся после `getUserMedia`;
  плюс защита от двойного входа в AR;
- поиск вершины навсегда замирал на «…», если IndexedDB запрещена;
- любой переход (карта, поиск, согласие с плашкой) объявлял регион выбранным
  вручную и навсегда гасил автоподбор по GPS — теперь это делает только выбор
  в настройках;
- двойной тап шёл по компасу, а не туда, куда ткнули;
- подписи кнопок не переводились при смене языка.

### Ложные вертикали на контурах склонов (решено)

Сквозь кадр протягивались крутые линии, не отвечающие рельефу: полилиния
силуэта рвалась при разрыве по горизонтали, но не по вертикали, а соседние лучи
(0.1°) могут попасть на край гребня и дно долины за ним. Разрыв полилинии при
скачке угла круче `MAX_RIDGE_SLOPE` (`buildRidgeSegments`), тест
`test/panorama.test.ts`.

### Вулканы отсутствовали в данных вершин (решено)

Эльбрус не подписывался, хотя стоишь прямо на нём: экстракторы брали только
`natural=peak`, а вулканы в OSM размечены `natural=volcano`. Вместе с Эльбрусом
терялись Казбек, Фудзи, Килиманджаро, Демавенд, Ключевская — и смысл целых
регионов реестра (Камчатка, Эквадор, Центральная Америка). `SUMMIT_TAGS =
("peak", "volcano")` в обоих инструментах, поле `volcano: true`; Приэльбрусье
1589 → 1605 вершин.

### Треугольник на своём склоне (решено)

Стоя на склоне Эльбруса (4127 м), гора рендерилась монолитным треугольником до
края экрана: заливка слоёв по дистанции хранила один max-угол на луч, поэтому
внутри фигуры не было информации о рельефе. Перешли на **видимые гребни**
(локальные максимумы угла вдоль луча) по корзинам дистанций `CREST_BOUNDS` с
окклюзией по running max, и на **контурный рендер без заливок** — двойная линия
со сдвигом (чёрная сверху, белая снизу) даёт контраст поверх кадра камеры.
Полилиния рвётся там, где нет данных. Заодно вертикальный FOV стал выводиться
из горизонтального и пропорций холста (был фиксированный 25°, проекция сжата).
См. `src/core/horizon.ts`, `src/ui/panorama.ts`.

### Service Worker не собирался (решено)

Офлайн-режим и установка PWA не работали ни разу: приложение регистрировало
`sw.js`, но в `dist/` его не было — Vite собирает граф от `index.html`, а worker
должен быть отдельным самодостаточным файлом по стабильному адресу. Отдельная
сборка `vite.sw.config.ts` → `dist/sw.js` (iife, без хеша), версия — хеш
исходника: браузер считает worker обновившимся только при побайтовом изменении.

### Офлайн падал с «HTTP 503» (решено)

В скачанном регионе без связи вместо панорамы была ошибка 503: Service Worker
отвечает `503 Offline` на всё, чего нет в кеше, а сэмплеры считали любой ответ
кроме 200 и 404 фатальным — исключение убивало весь расчёт, хотя рельеф лежал в
IndexedDB. Вдобавок выбор источника рельефа был чисто сетевым. Теперь временный
отказ — это «тайла сейчас нет», а не крах (дыра не запоминается, с возвратом
сети тайл догрузится); источник выбирается `pickDemBase` по сети **или**
сохранённому индексу.

### Панораму дёргало на месте (решено)

Картинка прыгала на ±30° у неподвижного телефона: Android шлёт
`deviceorientationabsolute` (от севера) и `deviceorientation` (от произвольного
нуля), оба висели на одном обработчике. Относительное показание используется,
только пока абсолютного нет (iOS); плюс слежение с подавлением дрожания вместо
среднего (ALGORITHMS.md §3).

### Активный регион сбрасывался при перезапуске (решено)

Выбранный вручную регион жил только до закрытия вкладки — приложение снова
открывалось на Приэльбрусье. Теперь выбор хранится в localStorage вместе с
признаком «выбрано вручную»: автоподбор по GPS такой выбор не перебивает.

### Список регионов пропадал без сети (решено)

Офлайн в настройках был пустой список — нельзя переключиться даже на полностью
скачанный регион. `regions.json` брался только из сети (Service Worker кеширует
его network-first, но лишь если файл хоть раз запрашивался онлайн), а кеш данных
назывался по версии оболочки и удалялся при каждом обновлении приложения. За
этим нашлась вторая, более общая: ленивые чанки (настройки, карта, поиск)
попадали в кеш только по факту запроса — кто не открывал настройки при сети,
офлайн получал мёртвую кнопку. Теперь каждая успешная загрузка реестра ложится в
IndexedDB (`meta/regions`) и реестр читается при старте всегда; worker при
установке кладёт в кеш все чанки сборки (список подставляет
`vite.sw.config.ts`), а кеш данных отвязан от версии оболочки.

### Панорама исчезала при смене размера окна (решено)

Поворот телефона давал пустой экран до следующего пересчёта: `resize()` менял
`canvas.width/height` (это очищает холст), но перерисовку не вызывал. Добавлен
`draw()` в конце `resize()`; объявление `panorama` пришлось поднять выше —
`resize()` выполняется при загрузке модуля и падал на TDZ.

### Панорама висела на «Расчёт…» в dev-режиме (решено)

Vite в dev отдавал воркер горизонта как `type=classic` (по умолчанию) и при
этом НЕ бандлил его импорты — браузер получал сырой модуль с `import` и падал
с «Cannot use import statement outside a module»; расчёт не приходил никогда.
Лечится явным `{ type: "module" }` в `new Worker(...)`: с ним dev переписывает
импорты как положено. На прод-сборку не влияет — там воркер и так собирается
в один iife-файл (`worker.format` в vite.config.ts). Module workers — Safari
15+, наш минимум и без того выше.

### Камера замирала после блокировки экрана (решено)

После блокировки/разблокировки смартфона AR иногда показывал застывший
последний кадр: пока страница фоном, браузер приостанавливает камеру, а часть
платформ (Android Chrome) завершает трек совсем. Завершённый трек
(`readyState === 'ended'`) перезапрашивается через `getUserMedia` — разрешение
уже дано, диалог не всплывёт. Для живого трека решение точнее: слепое
переприсоединение потока на каждый `visibilitychange`/`focus`/`pageshow` (в том
числе на безобидный alt-tab на десктопе) само по себе даёт короткий пустой
кадр — поэтому сначала `waitForFrame()` ждёт реальный новый кадр
(`requestVideoFrameCallback`, а без него — сверка `currentTime`) и только если
кадр не пришёл, происходит жёсткое переприсоединение (`pause` → новый
`srcObject` → `play`). Флаг `resuming` не даёт трём почти одновременным
событиям одной разблокировки переприсоединять поток параллельно. `ended`-трек
в видимой вкладке (камеру отобрало другое приложение) тоже переоткрывается —
слушатель `ended` при каждой замене потока переезжает на новый трек.

### Android Chrome сворачивал AR в Picture-in-Picture (решено)

При уходе с экрана приложения (кнопка «домой», другое приложение) во время AR
Android Chrome автоматически сворачивал играющее полноэкранное `<video>`
камеры в плавающее PiP-окно — нам этот режим не нужен совсем. Лечится
`disablePictureInPicture = true` на элементе в `attachStream()` (ui/ar.ts):
свойство ставится на каждое переприсоединение потока, поэтому не теряется
при перезапуске камеры после блокировки экрана.

### Кнопка «Скачать» мигала прогрессом на уже скачанном регионе (решено)

Нажатие на кнопку скачивания на главном экране всегда запускало полный
прогон `downloadRegion`: скачивание вершин, перебор тысяч ключей пирамиды,
hi-слоя и Terrarium — даже когда всё уже лежало на устройстве. Человек видел
«Загрузка тайлов: 3200/3200» и ждал, хотя по сети не ушло ни байта.

Теперь перед запуском загрузки проверяется `isRegionIncomplete` (ui/download.ts):
по одному чтению IndexedDB на каждый нужный тайл — базовый, hi, детальная
зона. Всё на месте → показывается «Всё уже скачано — обновлений нет» и
загрузка не стартует. Несовпадение версии пирамиды («Устарело») намеренно
не считается неполнотой: тотальное удаление тайлов при смене версии
иначе сделало бы все регионы вечно неполными и стёрло бы смысл отдельного
предупреждения об устаревании.

### «Мёртвая» сеть держала загрузку минутами (решено)

Мобильный интернет с ограничениями (GitHub недоступен, но DNS/TCP SYN
проходят) — худший случай: браузерный fetch без таймаута ждёт до TCP-таймаута
ОС, 30–60 секунд и дольше. Всё это время приложение висело на «Загрузка
региона…», хотя в IndexedDB лежали и реестр, и пирамида, и тайлы.

Теперь все запросы, ведущие к офлайн-фолбэку, идут с `fetchWithTimeout`
(core/fetch-timeout.ts, `AbortSignal.timeout`, 8 с): реестр регионов,
пробы `index.json` (initDemForRegion), пики региона, DEM-тайлы (DemSampler),
Terrarium-тайлы, поисковый индекс. Данные либо приехали за 8 секунд, либо
сеть мёртвая — приложение уходит в офлайн-режим за секунды, а не минуты.

### Тост об устаревшем рельефе: кнопка, не в офлайне, не чаще раза в сутки

Раньше тост показывался при каждом запуске, 12 секунд, без кнопки действия.
Это приводило к привыканию (человек перестаёт читать ежедневные тосты) и к
бесполезности в горах: без связи перекачать нельзя, а сообщение закрывает
панораму.

Теперь: 20 секунд (заметнее, но не блокирует), кнопка «Настройки» прямо в
тосте, подавление при `!navigator.onLine` (в горах не мешает), и не чаще
раза в сутки (localStorage `vershiny-outdated-toast-at`).

### «Фото с подписями» из AR: без кадра камеры, «сохранено» без файла (решено)

Два бага одной кнопки, замечены на Samsung S25 Ultra.

**В снимке не было фото с камеры.** `capturePhoto` рисовал на offscreen-холсте
только `renderPanorama` — градиент неба, контуры и подписи. Видео камеры туда
не передавалось никогда: оно рисуется лишь на экранный холст в `drawArFrame`
(ui/ar.ts). Итоговый PNG содержал контуры склонов поверх нарисованного неба.
Теперь в `capturePhoto` передаются `cameraVideo` и `cameraFov`
(ArSession.fullFrameFov): кадр видео рисуется cover-кропом, как на экране, а
оверлей пересчитывается через `applyCoverCrop` под видимую часть кадра —
иначе подписи совпадали бы с горами в центре и расходились к краям.

**«Снимок сохранён» без файла.** `savePhoto` удалял `<a download>` из DOM
сразу после `click()`. Android Chrome начинает скачивание blob асинхронно —
к моменту старта элемент уже вне документа, и загрузка терялась молча
(гонка: отсюда «иногда»). Теперь anchor удаляется через минуту, вместе с
`revokeObjectURL`.

### «К моему положению» всегда кричала об ошибке (решено)

Кнопка звала общий `getPosition()`, который обслуживает СТАРТ приложения и при
наличии точки прошлого запуска возвращает её мгновенно с `trusted: false` —
не спрашивая GPS вовсе (это осознанный компромисс: «показать что-то сразу,
спутники дослушать в фоне»). Обработчик кнопки любой `trusted: false` считал
отказом, поэтому после первого же успешного фикса в памяти приложения кнопка
железно выводила «Не удалось определить положение» — при полностью рабочей
геолокации. Теперь у кнопки свой путь: `getFreshPosition()` (core/position.ts)
идёт только к живым источникам — готовый фикс системы, затем спутники — и
честно отвечает `null`, если геолокация недоступна. Вчерашняя точка и
запасной Приют 11 как «ответ кнопки» больше не подставляются.

### Плашка «поводите восьмёркой» не пропадала на Android (решено)

Точность компаса −1 — это iOS-семантика («магнитометр раскалиброван», крутите
восьмёрку). Но в `core/orientation.ts` −1 присваивалась и там, где
`webkitCompassAccuracy` отсутствует в принципе, — то есть КАЖДОМУ сенсорному
показанию на Android. Итог: на Samsung плашка с просьбой калибровки висела
вечно, и никакая восьмёрка её не снимала. Теперь без webkit-полей точность —
честный `NaN` («неизвестно», а не «плохо»), а просьба по событию
`compassneedscalibration` без возврата точности сама гаснет через 15 с тишины
(на Android событие приходит повторно, пока датчик плох; замолчало — значит,
откалибровался). Регресс покрыт тестами в `test/compass.test.ts`.

## Архитектура данных

```
Слой 0 (онлайн): AWS Terrarium z9–z15 (весь мир, точнее в ближней зоне)
  ↓ fallback
Слой 1 (офлайн, детальный): hi-пирамида ~87 м — agran/vershiny-dem-hi → Pages,
  tiles/hi/0/{x}/{y}.bin.gz. Разрежена: регионы p1–p3 целиком (квант 2 м),
  остаток бюджета — самые горные ячейки p4 (Анды, Гималаи, Аляска, Тибет)
  ↓ fallback
Слой 2 (офлайн, базовый): глобальная пирамида GLO-90 — agran/vershiny-dem
  → Pages, tiles/global/{lod}/{x}/{y}.bin.gz
  (217 м / 435 м / 1.7 км, gzip + дельта; плюс детальные патчи /tiles/{region})
  ↓ fallback
Слой 3 (кеш): IndexedDB — тайлы хранятся как есть, сжатыми
  (dem-tiles: gzip-байты пирамид, terrarium: PNG, peaks, meta: index.json)
```

Клиент подключает до трёх локальных источников сразу
(`dem-config.ts` → `initDemForRegion`): детальный патч региона / hi-слой /
базовая пирамида. `DemSource` классифицирует каждый по разрешению
(`finestResM ≤ 120 м` — «свой», всегда приоритетнее Terrarium; грубее —
офлайн-запас вдали) и идёт по цепочке до первого NaN. Hi-слой и базовая
пирамида работают вместе: первый разрежён по приоритетным регионам, вторая
добирает остальное.

### Офлайн-загрузка региона

Кнопка «Скачать» берёт три слоя под разные задачи:

| Слой                                 | Что                   | Объём                  |
| ------------------------------------ | --------------------- | ---------------------- |
| Пирамида по всему bbox               | далёкие хребты, 217 м | 1–10 МБ                |
| Hi-слой по всему bbox (p1–p3)        | весь регион, ~87 м    | 0 (p4) — 40 МБ (Алтай) |
| Terrarium в круге 30 км вокруг точки | ближняя зона, 90 м    | ~7 МБ                  |
| Пики региона                         | подписи               | 0.2–0.5 МБ             |

Hi-слой разрежён: за порогом рельефа (100 м с весом приоритета) тайлов нет, а
до p4 он доходит только в самых горных ячейках; у приоритетных p1–p3 он —
главная часть закачки. Замеры по реальным тайлам (DEM без пиков): Эльбрус
12.7 МБ (hi 10.4), Эверест 5.6 МБ (hi 4.5), Камчатка-юг 7.2 МБ (hi 5.9),
Хибины 25.2 МБ (hi 20.6), Алтай 50.6 МБ (hi 40.3) — плюс Terrarium ~7 МБ и
пики.

**Дедупликация слоёв (2026-08-18).** Базовый LOD 0 (217 м) в ячейках 1°,
полностью покрытых hi-слоем (87 м), не скачивается — hi строго детальнее и
так входит в закачку (`keepBaseTileKey` в ui/download.ts; ячейка считается
покрытой только при всех 25 hi-тайлах 0.2°, береговые/дырявые ячейки базовый
слой страхует). Экономия p1–p3 — до ~30–40% базовой части (например, Алтай
экономит ~4 МБ). Если hi-слой недоступен (репозиторий лежит, офлайн-старое
устройство), качается вся базовая пирамида как раньше. Оценка размера в
настройках учитывает дедупликацию (фильтр в `bboxDownloadBytes`).

Регионы, скачанные до появления hi-слоя, перекачивать целиком не нужно:
кнопка «Скачан» у них оживает в «Обновить» (проверка `hasHiDetail` — есть ли
хоть один тайл LOD 0 в хранилище), а `downloadRegion` идемпотентен и докачает
только недостающие hi-тайлы, не трогая старые.

Медиана по 124 регионам — **13 МБ**; у p1–p3
прибавка hi: от ~5 МБ (Эверест) до ~40 МБ (Алтай). Приэльбрусье — 8.2 МБ без
hi, ~20 МБ с ним. Размер в панели настроек считается по реальному числу
тайлов в bbox (карта покрытия из `index.json` + `avgTileBytes` по LOD), а не
по площади: разреженная пирамида не хранит море и равнины, разница доходит
до порядка.

Прошлая схема качала Terrarium z9–z12 по всему bbox и хранила распакованным
(Float32, 256 КБ на тайл): медианный регион — 8.6 тыс. тайлов ≈ **2.2 ГБ**,
Гренландия ≈ 160 ГБ, при подписи «~10 МБ». Такая загрузка не могла завершиться
— упиралась в квоту браузера. Заодно в той же формуле молча терялись регионы
через антимеридиан (Врангель: `x0 > x1` → 0 тайлов) и с полюсом в bbox
(Антарктида: `tan(±90°)` → NaN → 0 тайлов).

## Производительность

| Метрика                | Значение                           |
| ---------------------- | ---------------------------------- |
| Панорама 360° (worker) | ~2 сек (первый раз), ~200 мс (кеш) |
| Тайлы Terrarium        | 66 тайлов / 2 сек (z9–z12)         |
| Память                 | ~50 MB (DEM + пики)                |

Ray-marching оптимизирован (2026-08-19, без потери точности), два этапа.
**Этап 1**: таблица шагов и sin/cos(d/R) общая для всех 3600 лучей; константы
наблюдателя и азимута вынесены из `destination` в `makeRayMarcher` (точки
бит-в-бит те же — есть тест); горячие циклы сравнивают наклоны вместо углов
(atan2 монотонна), трансцендентные функции — только при обновлении максимумов
и записи (~2 млн atan2 убрано из марша); кеш последнего тайла в обоих
сэмплерах; объект точки луча переиспользуется (минус ~2 млн аллокаций); луч
пика обрывается досрочно, когда глубина под профилем доказанно превысила порог
hidden. **Этап 2**: таблица марша несёт подсказки шага — `earthDrop`, LOD
пирамиды и зум Terrarium предвычислены по дальности (логарифм `lodForDistance`
и перебор `ZOOM_RULES` ушли из горячего цикла); `DemSource.sample` кеширует
последний успешный источник (порядок опроса не меняется — `covering()` зовётся
только при промахе кеша); фронты луча собираются в SoA-массивах, объекты
`VisibleFront` аллоцируются раз на луч; при декодировании int16-тайла считается
`tileMax` (задел для точного отсечения луча по верхней границе высоты).
Бенчмарк ядра марша (3600×~540 шагов, синтетический сэмплер): 250 → 171 мс
(×1.45); контрольная сумма профилей совпала. На реальном DEM выигрыш больше
за счёт кешей тайла и источника — замер на устройстве в планах.

Сетевой и кадровый путь (2026-08-19, аудит docs/PERFORMANCE-AUDIT.md):
пробы индексов параллельны (выбор первого подошедшего по исходному приоритету)
и с коротким таймаутом 2.5 с вместо общего 8 с; при `navigator.onLine === false`
сетевые пробы пропускаются целиком (только IndexedDB) — мёртвая сеть перестала
умножать таймауты на цепочки кандидатов. Service Worker кладёт в прекэш только
оболочку при install; чанки приложения докачиваются по сигналу «первая панорама
готова» (PRECACHE_READY) или по таймеру 60 с после активации — первый расчёт
больше не делит соединения с ~20 чанками. Рендер: события ориентации и мыши
сливаются в один кадр через rAF (было: полный рендер на каждое событие, до
60+ Гц); при активной AR-сессии обычный draw() пропускается (кадр рисует её
rAF-цикл — раньше панорама рисовалась и тут же затиралась видео);
silhouetteProfile кешируется по ссылкам массивов панорамы (~47 тыс. итераций
и аллокация 14 КБ уходят из кадра), буфер окклюзии runningMax переиспользуется.

Кадровый путь, вторая партия (тот же день, мозговой штурм по GPU — пункты
№1/№2). Рендер по датчику — только когда взгляд сместился на ≥ полпикселя от
последнего отрисованного кадра (`viewDrifted` в main.ts): heartbeat
`emitSensorState` (10 событий/с в покое) и дрожание компаса раньше гоняли
полный `renderPanorama` впустую; порог считается от последнего ОТРИСОВАННОГО
кадра, поэтому медленный дрейф накапливается и плавность не страдает. Крен
(rollRad) порог не учитывает: вне AR он влияет только на невидимый запас за
краями холста (`rollEdgeMarginX`), а в AR обычный draw() и так не рисует.
Разрешение холста ограничено DPR ≤ 2 (`MAX_DPR`): на 4K@200% это 3840×2160
вместо 7680×4320 (заливка, stroke и композитинг растут с квадратом плотности,
разница 2 vs 3 на линиях 1.4 CSS px и тексте 13 px глазу не видна), а на
время ручного поворота (мышь/свайп без датчиков — основная нагрузка на
десктопе) плотность падает до 1 (`DRAG_DPR`) и возвращается на pointerup
тем же событием с финальным чётким кадром. В AR и при сенсорном источнике
понижение не включается: там холст занят видео, а свайп — редкая подстройка
калибровки. Проверено вживую: при DPR 3 холст 5120 вместо 7680 (кап), на
pointerdown 2560 (понижение), на pointerup обратно 5120.

Кадровый путь, третья партия (тот же день, штурм №4–№6). **Кэш сцены при
непрерывном движении** (`drawFromSceneCache` в main.ts): пока кадры идут
серией (drag, поворот по датчику — ≥3 кадров за 0.5 с), панорама рендерится
в offscreen-холст с полями запаса (min(25 % экрана, 512×384 px)) и дальше
каждый кадр — один `drawImage` со сдвигом; полный рендер только когда взгляд
вышел за поля (перерендер с перецентровкой). Масштаб кэша (px/рад) совпадает
с экранным — fov кэша шире ровно во столько, во сколько шире холст; по
вертикали опорная точка — линия горизонта (HORIZON_FRAC). Одиночные кадры
рисуются напрямую, без кэша. Через 200 мс после остановки движения —
один чёткий прямой рендер (blit с дробным сдвигом мылит на субпиксель),
память кэша освобождается. Инвалидация — по содержимому: новый результат
воркера, смена региона, смена языка (`sceneDirty`); по геометрии: размер
холста и fov. Замер вживую на десктопе: из 20 кадров drag 17 — чистый blit
(ни одного stroke/measureText), 3 — полные рендеры. **Децимация гребней
RDP** (`decimateSegments`): точки сегментов прореживаются с гарантированной
ошибкой ≤ 0.5 px устройства — на скалистой «пиле» уходит треть точек, на
пологих дугах до 90 %; stroke (два прохода) дешевеет пропорционально.
Ловушка, пойманная замером до коммита: поточная децимация «по хорде к
следующей точке» накапливает до 7·ε на длинных дугах (3.4 px на параболе) —
поэтому полноценный Ramer–Douglas–Peucker итеративным стеком. **Стыки линий
bevel вместо round** (дуга на каждой из тысяч вершин была невидима на линии
1.4 CSS px); концы сегментов остаются round. **Кэш `measureText`** (кегль +
текст → ширина, потолок 4000 ключей) и **кэш градиента неба** (зависит
только от высоты холста) — мелочь из каждого кадра убрана. backdrop-blur
остался только на подложке панели настроек (открыта редко, панорама под ней
в покое) — осознанно не трогаем.

Кадровый путь, четвёртая партия (тот же день, штурм №3 — AR-оверлей).
**Оверлей AR в offscreen + blit** (`drawArOverlayCached` в ar.ts): контуры и
подписи рисуются в два offscreen-холста (линии полупрозрачно, подписи
непрозрачно) с запасом 45 % по краям и перерендериваются только по порогам:
дрейф азимута за половину запаса, наклон дальше 4 px, смена peaks/layers/fov/
зума, либо регламентно раз в 30 кадров (кластеризация подписей — снимок на
момент рендера). Каждый живой кадр — clearRect плюс два blit с поворотом на
текущий крен (roll идёт в `rotateAroundCenter` вокруг центра экрана, а не в
перерендер): полный рендер оверлея ~10–20 мс заменяется двумя `drawImage`
~0.2 мс. Центр запаса квантуется (шаг 25 % от запаса), чтобы опора не
прыгала при каждом перерендере и подписи не «плыли». Память освобождается
при выходе из AR (`stop()`). Тесты: 6 новых в `ar-overlay-cache.test.ts`
(первый кадр — рендер, далее blit; крен — поворот, не перерендер; пороги
азимута/наклона/контента/регламента).

**Развязка видео и оверлея (аудит 5.2)**: видео ушло на отдельный слой-канвас
под основным холстом (`#app`, та же сетка CSS), обновляется только по
реальным кадрам камеры (`requestVideoFrameCallback`, 30–50/с), оверлей — по
rAF ≤ 60/с поверх; два холста композитятся браузером. Раньше видео
рисовалось в каждом кадре цикла (до 60/с) — вдвое больше decode→upload, чем
отдаёт камера. Цепочка rVFC перевзводится, если кадры камеры пропали (пауза/
сворачивание), а при смене геометрии (поворот окна, resize, новый поток)
слой перерисовывается даже без нового кадра; без rVFC (ниже минимума
Safari 16.4) видео идёт по rAF, как раньше. Пойманная ловушка: оба холста в
`#app` — статичные блоки, и слой в нормальном потоке занял бы верхние 100 %
высоты, столкнув холст с контурами за кадр — слой позиционируется absolute
(`inset:0;z-index:-1`) поверх той же области. Регрессионный тест в
`ar.test.ts`. Пойманная ловушка №2: `drawOverlay` считает проекцию от
размеров ХОЛСТА, а кэш рендерил оверлей на буфере с полями запаса
(1770×752 → 3364×1428) — проекция растягивалась в 1.9× вокруг центра
экрана, и контуры падали ниже холста (симптом: контуры видны до первого
кадра камеры, с его появлением «уезжают под экран»). В `OverlayOptions`
добавлены `viewWidth/viewHeight` — геометрия кеша считается от видимой
области, холст остаётся только поверхностью; регрессионный тест в
`panorama.test.ts` (горизонт на 0.62·viewHeight, а не 0.62·bufHeight).
Замер с телефона (S25 Ultra):
камера отдаёт 1080×1920 при 30–50 кадров/с — видео-дроу сократились с 60/с
до фактической частоты камеры (счётчик `videoDraw` в `?perf`, `cam:` — в
`?ardebug`).

Ядро марша, третья партия (тот же день, побитово): корзина слоя предвычислена
в таблице марша (`bin[s]` — функция только от дистанции, из цикла ушёл перебор
5 границ × 1.9 млн итераций); четыре буфера состояния бинов переиспользуются
между лучами (−14.4 тыс. аллокаций на расчёт); все типизированные буферы
результата уходят в main-поток трансферами (без копирования), а фронты —
в плоском SoA (Float32Array четвёрок + Uint32Array оффсетов, объекты собирает
main) вместо structuredClone 3600 массивов. Полный проход computeLayeredHorizon
на синтетике: 191 → 133 мс (с начала дня 250 → 133 мс, ×1.9).

Пойманная ловушка: `normalizeLon(x)` НЕ тождественна `x` даже внутри
[−180, 180) — цепочка остатков даёт 1-ulp сдвиг, ответ зависит от направления
к антимеридиану. «Условная normalizeLon» из аудита №3.2 побитово невозможна
(тест «makeRayMarcher ≡ destination» это поймал); оставлена как есть.

Старт на больших регионах (2026-08-19, аудит №5): первая панорама больше не
ждёт вершины. Стартовый `compute` уходит сразу после выбора источников DEM
с пустым списком вершин (силуэт — это DEM, пики нужны только подписям);
вершины грузятся фоном (сеть → IndexedDB), изоляция сначала читается из кеша
(`getIsolation`/`saveIsolation` в meta, ключ `iso:{region}` — изоляция есть
функция набора вершин и не зависит от точки), а не считается заново. Когда
вершины готовы и ни регион, ни точка за это время не сменились, они
докидываются вторым `compute` той же точки (рельеф уже посчитан). На iberia
(49 тыс. вершин, 4.8 МБ) это убирает ~0.6–1 с из критического пути первого
кадра на телефоне; на маленьком elbrus разница копеечная, но путь теперь
один и тот же для всех регионов. Тот же кеш изоляции использует смена
региона (`switchRegion`).

**Аудит №4 (обрыв луча по верхней границе высоты) — исследован и отклонён
(2026-08-19).** Идея: хвост луча, где даже верхняя граница высоты региона
не пробивает текущий максимум, можно пропустить. Анализ и реализация
показали, что это не работает при сохранении побитовости:

- В слоистом марше обрыв блокируется самым дальним бином (100–200 км): пока
  он не набрал максимум в своём диапазоне, хвост его потенциально поднимает,
  и обрыв невозможен до ~100 км — а там граница при положительном
  (regionMax − hO) ещё слишком высока, чтобы отсекать.
- Сравнивать границу только с видимым фронтом/гребнем нельзя: хвост реально
  поднимает дальний слой, и слои перестают совпадать побитово (поймано
  тестом «обрыв не меняет профиль»).
- Секторная схема (max по соседним тайлам) требует доказательства окаймления
  луча и второго марша на луч — сложность не окупается оценкой −10–35% только
  в горном случае.

В коде оставлены только данные: `loadedMaxHeight` (максимум высоты по
загруженным тайлам) в `DemSampler`, `TerrariumSampler`, `DemSource` —
пригодятся для диагностики и как задел, если появится корректная схема.
Тесты 407/407, профиль марша не изменён.

Скачивание (26 475 тайлов, ~175 ГБ в `dem/glo-90`) и конвертация **выполнены**:

Остаточные дыры у приоритетных регионов — океан внутри bbox (Гавайи, Тасмания).

Проверено в приложении (Приют 11): грузятся все три LOD, горизонт — 3600 лучей,

### Запас до лимита Pages: бенчмарк кодеков (2026-08-18)

В vershiny-dem свободно ~100–150 МБ до лимита 1 ГБ. Dry-run на реальных
тайлах показал, что кандидатов обрезает именно бюджет: LOD 0 влезло 1844 из
12147 ячеек, LOD 1 — 15 179 из 19 400. Варианты дозаполнения без смены
формата (замерено): поднятие бюджета до 980–1000 МБ → 917–936 МБ итого;
перекос в LOD 0 (0.60/0.30) → +21% горных ячеек; перекос + порог размаха
400→300 м → **+54% ячеек LOD 0** (низкогорья жмутся лучше), итого 936 МБ.

Бенчмарк кодеков на 250 случайных тайлах каждого LOD
(`tools/codec-bench/codec_bench.py`, база = текущий «дельта-x + gzip-9»):

| Кодек                            | LOD 0      | LOD 1  | LOD 2  | Итого              |
| -------------------------------- | ---------- | ------ | ------ | ------------------ |
| Paeth + gzip-9                   | 0.959×     | 0.975× | 0.985× | 0.969×             |
| PNG I;16 (Pillow)                | 0.972×     | 0.969× | 0.958× | 0.968×             |
| PNG RGB 2×8bit (декод браузером) | 1.043×     | 1.036× | 1.027× | **1.038× ❌**      |
| **Paeth + Rice (свой)**          | **0.785×** | 0.855× | 0.989× | **0.849×**         |
| Paeth + Exp-Golomb               | 0.927×     | 0.942× | 1.017× | 0.950×             |
| LSQ-плоскость + Paeth + Rice     | 0.795×     | 0.872× | 1.009× | 0.862×             |
| кросс-LOD + Paeth + Rice         | 0.828×     | 0.987× | —      | хуже простого Rice |
| delta-x + zstd-19                | 0.929×     | 0.925× | 0.921× | 0.926×             |

Выводы: «PNG-2×8bit, браузер декодирует бесплатно» — опровергнуто (младший
байт в отдельном канале жмётся хуже gzip). zstd не окупает wasm-декодер.
«Улучшайзеры» Rice тоже опровергнуты замером: Exp-Golomb хуже везде,
LSQ-плоскость даёт ~0 (Paeth сам снимает планарный градиент), предсказание
от апсемпла родительского LOD **хуже** соседского Paeth (шум кванта родителя
+ сглаживание билинейной интерполяции). Практический оптимум — простой
Paeth+Rice: **−15% объёма** (та же пирамида ~720 МБ, либо +18% контента в
1 ГБ). Цена — TS-декодер ~150 строк + миграция формата с magic-версией.
  **Решение отложено**: сначала простое дозаполнение бюджета, кодек — если
  лимит снова станет проблемой. Структурный выход при росте — третий
  шард-репозиторий (прецедент dem-hi).

Отдельно проверена идея «тайлы из GitHub Releases» (2026-08-18, curl с
Origin на чужом релиз-ассете): Range-запросы работают (206, Accept-Ranges),
но **CORS-заголовков нет** (ни на 302, ни на release-assets.githubusercontent.com,
OPTIONS → 404) — браузерный fetch такие файлы не прочитает. Releases как
хранилище тайлов для браузера не подходит без прокси/воркера.

Проверено замером дополнительно (2026-08-18, второй заход):

- **Квант 4 м на LOD 0** вместо 2 м: 0.799× по размеру тайла (−20%, ~99 МБ
  с уровня) — вертикальная ошибка кванта тонет в горизонтальной ошибке
  ячейки 217 м. Клиент менять не нужно, квант задан в index.json.
- **Дубли hi ↔ LOD 0**: тайлы LOD 0 в регионах p1–p3 (их же покрывает
  hi-слой 87 м) — **168 МБ из 478.6 МБ LOD 0** (35%). Онлайн дубль избыточен
  (hi приоритетнее, при его падении есть Terrarium ~90 м); нужен только как
  резерв офлайн-скачивания при недоступности dem-hi. Ревизия дублей —
  крупнейший нетронутый резерв, отдельная задача.
- **Вариант C + квант 4 м одной пересборкой**: LOD 0 влезает
  **4451 ячейка из 14175** против текущих 1844 — **+141% горных ячеек** при
  том же итоговом объёме ~936 МБ. Лучший найденный план дозаполнения.
  **Реализовано 2026-08-18** (итог: 947 МБ; доли уровней после замера
  уточнены до 0.60/0.30 — LOD 2 недобирал свою долю, ~104 из 150 МБ; плюс
  дедупликация офлайн-скачивания против hi-слоя — см. «Офлайн-загрузка
  региона»). Контроль: Приют 11 → 4134 м (было 4133 м — квант 4 м погрешности
  не добавил).
- ⚠️ **Гигиена git**: полная пересборка перезаписывает все 26 тыс.
  бинарников; при коммите поверх истории репозиторий (~820 МБ) удвоится и
  упрётся в лимит git раньше лимита Pages. Пересборки выкладывать
  orphan-branch / force-push одной ревизией.

Формат, схема LOD и команды — [DATA-PIPELINE.md](DATA-PIPELINE.md).
