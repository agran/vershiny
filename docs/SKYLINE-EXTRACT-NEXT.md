## Что есть сейчас и где ломается

`extractSkyline` (skyline.ts) — поколоночный порог Оцу по признаку
`0.6·яркость + 0.4·синеватость` на сетке 160×120, плюс два фильтра
(относительное разделение и абсолютный контраст MIN_CONTRAST=0.06).

Работает в ясный день. Ломается:
- дымка/туман: ловит «туман/ближний склон» вместо дальнего гребня;
- закат/низкое солнце: небо тёплое, «синева» отрицательна, розовый снег светлее неба;
- пасмурно: синева ноль, снежные поля на склоне принимаются за небо;
- ночь/сумерки: граница инвертирована или отсутствует, фонари — ложные точки;
- против солнца: засветка половины кадра;
- облака низко над гребнем: граница «небо/облако» есть, «облако/гора» — нет;
- лес/скала в тени vs небо в дымке: по яркости неотличимы.

## План: два этапа (A+C сразу, D потом), B — не делать

Источник идей: мозговой штурм (см. переписку 2026-08-17) + оценка применимости.
Ниже — проверенный на наш код план.

### Этап 1: мультипризнаковый экстрактор с ДП (подход A)

Замена поколоночного Оцу глобально-согласованной линией.

**Признаки на колонку** (по уменьшенному кадру 160×120, все дешёвые):
1. Градиент яркости `|∂Y/∂y|` (со знаком — пригодится ночью);
2. Градиент цветового вектора `|∂(B−R)/∂y|` и `|∂насыщенности/∂y|` — небо и земля
   различаются по вектору цвета, даже когда яркости равны (закат, пасмурно);
3. Скачок вертикальной текстуры: дисперсия яркости в окне 3–5 px выше кандидата
   vs ниже. Небо (даже облачное) гладкое после даунскейла, лес/скалы — шершавые.

**Проверка кандидата «небо сверху»**: область выше кандидата — низкая текстура
и гладкая яркость до верха кадра. Интегральные суммы дисперсии по колонке —
O(H) после префиксных сумм. Снежное поле на склоне эту проверку провалит.

**Выбор линии — ДП** (кратчайший путь слева направо):
`cost(x, y) = −strength(x,y) + λ·|y − y_prev|^1.5`, плюс состояние NONE
(«в этой колонке границы нет») с фиксированным штрафом. Ограничение наклона
Δ ≈ ±6 px между соседними колонками. λ — единственный «магический» параметр,
выносится в константы и подбирается на синтетике.

**Интерфейс не меняется**: возвращает `Float32Array(160)` долей высоты кадра
(NaN — нет границы) — матчер и тесты не трогаем.

**Цена**: ~2–5 мс на кадр в JS (признаки O(W·H) + ДП O(W·H·Δ)). Для кнопки
«Совместить с камерой» и автозапуска при входе в AR — в бюджете.

### Этап 1б: временна́я стабилизация (подход C)

Кольцевой буфер последних N≈8–15 профилей (~0.5 с видео):
- выравнивание между кадрами — кросс-корреляцией профилей (FFT у нас уже есть:
  `src/core/fft.ts`), НЕ гироскопом (deviceorientation шлёт с нестабильной
  частотой);
- итоговый профиль — помедианный по времени;
- метрика пригодности колонки: временна́я дисперсия `var_t(y(x))` после
  выравнивания. Граница «небо/гора» стоит, «небо/облако» ползёт — это физически
  честный детектор облаков над гребнем, лучше любых порогов Оцу.

Побочный выигрыш: усреднение давит шум сенсора — ночью граница проявляется там,
где на одном кадре её нет.

### Этап 2 (позже, после полевых испытаний этапа 1): guided search по форме DEM

После первого совмещения модельный силуэт даёт ожидаемую линию. Искать
кандидатов в полосе ±10–15° возвышения вокруг неё, со штрафом не за положение
(сдвиг неизвестен), а за расхождение **производных** `|dy/dx − dy_model/dx|`
(форму DEM знаем точно, сдвиг — нет).

⚠️ Циркулярность: профиль ищем по модели, модель совмещаем по профилю. Защита:
(a) только производные формы, не абсолютное положение; (б) раз в секунду —
слепой прогон этапа 1 и сверка: расходятся — полосу расширить; (в) в матчер
отдавать оценку уверенности.

### Подход B (иерархия слоёв по дымке) — НЕ делать как извлечение

Внутренние гребни по дальности у нас уже есть (`panorama.crests` — корзины
дистанций из DEM). Извлекать их из кадра через «замешивание в цвет неба»
хрупко на закате (переэкспонированное небо у солнца даёт ложный эталон).
Если понадобится выбор этажа — решать на стороне матчера через существующие
crests, не через новый экстрактор.

## Синтетические тесты (обязательны)

Расширить `renderFrame` из `test/skyline.test.ts` погодными параметрами:

```ts
renderFrame(profileTrue, weather) // weather: {skyGradient, hazeDensity,
                                  // sunAzimuth, cloudLayer, noiseσ, exposure}
```

Матрица: 7 погодных режимов (ясно / дымка / закат / пасмурно / сумерки /
против солнца / облака над гребнем) × 3 рельефа. Метрики: медианная и
95-перцентильная ошибка |y_est − y_true| по колонкам, доля ложных NaN и ложных
не-NaN. Пороги — в тестах, чтобы регрессии ловились автоматически.

## Куда это втыкается
