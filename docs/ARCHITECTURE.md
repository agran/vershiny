## Ключевые решения

| Решение | Почему |
|---|---|
| Canvas 2D, проекция (азимут, возвышение), без 3D-движка | Пики на 200 км ломают float32 в WebGL; в 2D-проекции проблемы нет. Меньше зависимостей, работает на слабых устройствах |
| Ray-marching в Web Worker | Не блокирует UI; <500 мс на панораму 360° |
| Высота наблюдателя из DEM, не из GPS | GPS-альтиметрия врёт на ±50–100 м → силуэт «плывёт» по вертикали |
| Глобальный DEM = AWS Terrarium, свои тайлы — только патчи | Весь мир из коробки без ETL; >60°N закрыто ArcticDEM/GLO-90 внутри Terrarium; свой хостинг — только горные регионы (DATA-PIPELINE.md) |
| Единая абстракция DemSource (патч → Terrarium → кеш) | Ray-marching не знает об источнике; точка расширения для новых слоёв |
| Прекомпилированные статические данные | Никакого бэкенда и никаких рантайм-запросов к Overpass (rate limits) |
| AR-first на телефоне, панорама — фолбэк | Основной сценарий — «стою на склоне и навожу телефон»: подписи поверх живого кадра отвечают на вопрос сразу, без сличения рисунка с местностью. Поэтому камера включается сама при запуске (отказ запоминается). Но рендер один и тот же, и без камеры — с отказом в доступе, на десктопе, с врущим компасом — панорама работает целиком |
| Положение в два этапа: грубое сразу, точное потом | Без сети холодный GPS-фикс занимает минуты (нет A-GPS), и приложение висело на заставке. Сначала берём точку прошлого запуска или сетевое положение и рисуем панораму, затем молча уточняем по спутникам и пересчитываем, если сдвиг существенный (`core/position.ts`) |
| Каждый слой поверх панорамы — запись в истории браузера | Системный жест «назад» на Android и свайп от края на iOS — то же действие, что крестик. Без записи в истории жест выбрасывал из приложения. Стопка слоёв в `ui/overlay-history.ts`: один слушатель `popstate` закрывает только верхний слой (слушатели на каждом слое закрывали бы все сразу) |
| Приватность по умолчанию | Подпись снимка с координатами и временем выключена, пока её не включили в настройках: снимком делятся, и место съёмки не должно уезжать вместе с ним незаметно. По той же причине в счётчик посещений уходит адрес без параметров `?lat=&lon=` (`core/analytics.ts`) |

## Система координат проекции

Для точки наблюдения O и цели P:
- `azimuth = atan2(Δλ·cos φ, Δφ)` (сферическое приближение достаточно; погрешность << шага сетки)
- `elevationAngle = atan2(h_P − h_O − drop(d), d)`, где `drop(d) = d²·(1−k)/(2R)` —
  кривизна Земли с рефракцией, k≈0.13, R=6371 км
- Экран: `x = (azimuth − centerAz) / fov · width`, `y = horizonY − elevationAngle / fovV · height`

Все азимуты — истинные. Компас отсчитывает от **магнитного** севера, поэтому
склонение добавляется автоматически по модели WMM-2025 (`core/declination.ts`),
как только известно физическое положение устройства; ручная подстройка свайпом
остаётся для локальных аномалий (железо рядом, дешёвый магнитометр).
Солнечная калибровка даёт истинный азимут напрямую.
