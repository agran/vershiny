## Ключевые решения

| Решение | Почему |
|---|---|
| Canvas 2D, проекция (азимут, возвышение), без 3D-движка | Пики на 200 км ломают float32 в WebGL; в 2D-проекции проблемы нет. Меньше зависимостей, работает на слабых устройствах |
| Ray-marching в Web Worker | Не блокирует UI; <500 мс на панораму 360° |
| Высота наблюдателя из DEM, не из GPS | GPS-альтиметрия врёт на ±50–100 м → силуэт «плывёт» по вертикали |
| Глобальный DEM = AWS Terrarium, свои тайлы — только патчи | Весь мир из коробки без ETL; >60°N закрыто ArcticDEM/GLO-90 внутри Terrarium; свой хостинг — только горные регионы (new-geo-data.md) |
| Единая абстракция DemSource (патч → Terrarium → кеш) | Ray-marching не знает об источнике; точка расширения для новых слоёв |
| Прекомпилированные статические данные | Никакого бэкенда и никаких рантайм-запросов к Overpass (rate limits) |
| AR-first на телефоне, панорама — фолбэк | Основной сценарий — «стою на склоне и навожу телефон»: подписи поверх живого кадра отвечают на вопрос сразу, без сличения рисунка с местностью. Поэтому камера включается сама при запуске (отказ запоминается). Но рендер один и тот же, и без камеры — с отказом в доступе, на десктопе, с врущим компасом — панорама работает целиком |

## Система координат проекции

Для точки наблюдения O и цели P:
- `azimuth = atan2(Δλ·cos φ, Δφ)` (сферическое приближение достаточно; погрешность << шага сетки)
- `elevationAngle = atan2(h_P − h_O − drop(d), d)`, где `drop(d) = d²·(1−k)/(2R)` —
  кривизна Земли с рефракцией, k≈0.13, R=6371 км
- Экран: `x = (azimuth − centerAz) / fov · width`, `y = horizonY − elevationAngle / fovV · height`

Все азимуты — истинные (магнитное склонение компенсируется ручной подстройкой;
солнечная калибровка даёт истинный азимут напрямую).
