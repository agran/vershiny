# Алгоритмы

## 1. Горизонт: ray-marching по азимутам

Это **не** total viewshed (CacheTVS/XPDERL избыточны и GPL) — считаем только профили лучей из одной точки.

```
для az в 0..360° с шагом 0.1–0.2°:        # 1800–3600 лучей
    maxAngle = −∞
    для d от 100 м до 200 км с растущим шагом:   # 90 м вблизи → 500 м+ вдали
        (φ, λ) = destination(O, az, d)
        h = sampleDEM(φ, λ) + drop(d)            # кривизна Земли + рефракция k≈0.13
        maxAngle = max(maxAngle, atan2(h − h_O, d))
    horizon[az] = maxAngle
```

- LOD-выборка: d<30 км — слой 90 м, дальше — 500 м
- Стоимость: ~2.5M сэмплов из типизированных массивов → **<300–500 мс в worker**
- Пересчёт: сдвиг >100 м **или** Δh >20 м; при повороте камеры пересчёт не нужен
  (панорама 360° кешируется целиком)
- Узкие дальние гребни могут попасть между лучами (undersampling) — поэтому пики
  проверяются отдельными точными лучами (см. ниже)

## 2. Видимость пика

Для каждого пика в радиусе 200 км — один луч в его азимуте:
`видим ⟺ угол(пик) ≥ maxAngle(луч до пика) − ε`. Дёшево (~700 сэмплов × N пиков).

## 3. Калибровка компаса (лестница от простого к сложному)

| # | Подход | Трудоёмкость | Точность | Статус |
|---|---|---|---|---|
| 1 | Свайп-подстройка пользователем, оффсет на сессию | S | как глаз | **MVP** |
| 2 | Комплементарный фильтр: гироскоп (быстро) + магнитометр (медленный якорь) | S/M | убирает дрожание, дрейф остаётся | **MVP** |
| 3 | **По солнцу/луне**: тап по солнцу в кадре → suncalc даёт истинный азимут ±0.5° | M | ±0.5–1° | **v1.1, killer-фича** |
| 4 | CV: 1D-кросс-корреляция профиля «небо/земля» из кадра с DEM-панорамой 360° | L | ±1–2°, нестабильна при облаках/лесе | **v2.0**, кнопка, не realtime |
| 5 | Полный фильтр Калмана (сенсоры+CV+GPS-трек) | L+ | — | только если 1+3+4 не хватило |

Детали №4 (дешевле гомографии):
```
профиль кадра:  для каждой колонки x — y первого сильного градиента яркости сверху
                → угол возвышения α_frame(x)
корреляция:     сдвиг Δaz = argmax corr(α_frame(x), α_dem(az + x·fov/width))
                + оценка доверия (пик корреляции / шум); при низком доверии — «не удалось, подстройте вручную»
```

## 4. Проекция подписей и кластеризация

- Угловые координаты → экран (формулы в ARCHITECTURE.md)
- Вертикаль FOV камеры устройства — из `MediaTrackCapabilities` где доступно, иначе калибровочная константа ~50° и настройка в UI
- Наложение подписей: жадная расстановка по `score = ele/distance`, конфликтующие — в кластер «+N»

## 5. Чего избегать

- three.js/WebGL для MVP-проекции (float32 на 200 км, лишний вес)
- Запросы к Overpass из приложения (rate limits, офлайн)
- GPS-высота как источник истины
