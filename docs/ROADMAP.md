# Дорожная карта «Вершины»

Open-source аналог PeakFinder: веб-PWA, которое по камере/компасу телефона
показывает силуэт горизонта и подписи горных вершин. Офлайн-first, данные OSM + открытые DEM.

## Стратегический принцип

**MVP — это панорама на Canvas 2D с быстрым ray-marching и ручной подстройкой,
а не AR с автокалибровкой.** AR и CV — эволюция, не фундамент.
Рендер — 2D-проекция (азимут, угол возвышения) → не нужен WebGL/three.js,
исчезает проблема точности float32 для пиков на 200+ км.

## Этап 1. MVP «Панорама» (недели 1–4)

### Неделя 1 — пайплайн данных + ядро горизонта
> 1.3 и 1.4 идут параллельно с 1.1–1.2: ядро работает на Terrarium (слой 1)
> без ожидания пайплайна патчей. ✅ Ядро и оба инструмента уже реализованы.
- [x] 1.1 Скрипт `dem-to-tiles`: GeoTIFF → бинарные тайлы 256×256 int16 + JSON-индекс,
      разноуровневое разрешение (90 м в радиусе 30 км от центра региона, 250–500 м дальше)
- [x] 1.2 Скрипт `peaks-to-json`: Overpass → компактный JSON региона
      (прекомпилированный, никаких запросов к Overpass из приложения в рантайме!)
- [x] 1.3 Ray-marching горизонта в Web Worker: 3600 лучей × адаптивный шаг,
      кривизна Земли + рефракция (k≈0.13); источник высот — DemSource (патч → Terrarium)
- [ ] 1.4 Бенчмарк на реальном телефоне: цель <500 мс на полную панораму 360°
- [x] 1.5 **Треугольник на своём склоне**: решён переходом на контурный рендер видимых
      гребней вместо заливки слоёв (см. STATUS.md «Решённые проблемы»)

**Критерий:** панорама для точки у Приюта 11 совпадает с реальным профилем Эльбруса/Донгузоруна.

### Неделя 2 — рендер и ориентация
- [x] 2.1 Canvas 2D: силуэт горизонта, шкала азимутов, подписи пиков (название, высота, км)
- [x] 2.2 Поворот пальцем (работает всегда, без сенсоров — fallback-режим)
- [x] 2.3 `deviceorientation absolute` + комплементарный фильтр (гироскоп — быстро, компас — якорь)
- [x] 2.4 Кластеризация подписей при наложении: приоритет = высота + бонус за близость,
      подписи под одним углом с якорем на вершине, вытесненная подпись не рисуется
- [x] 2.5 Слои дальности: гребни по корзинам дистанций с окклюзией (контуры, не заливка)

**Критерий:** на телефоне панорама следует за поворотом плавно, без дрожания.

### Неделя 3 — позиционирование и калибровка
- [x] 3.1 GPS + **высота из DEM по координате** (не из GPS — врёт на ±50–100 м)
- [x] 3.2 Ручной выбор точки на карте (fallback при плохом GPS в ущелье)
- [x] 3.3 Свайп-подстройка азимута («совместите силуэт с горами»), оффсет на сессию
- [x] 3.4 Пересчёт горизонта на смену точки наблюдения; повороту камеры пересчёт не нужен
      (панорама 360° считается целиком). Порог 500 м — у автоматического уточнения по GPS
      (ALGORITHMS.md §8); ленивый пересчёт видимого сектора не понадобился
- [x] 3.5 Навигация: WASD/стрелки, nav pad, кнопки высоты ±100м, индикатор высоты

**Критерий:** полевой тест — подписи наведены ручной подстройкой за <10 сек.

### Неделя 4 — AR и офлайн
- [x] 4.1 AR-режим: `getUserMedia` + полупрозрачный оверлей той же проекции
- [x] 4.2 PWA: Service Worker + IndexedDB, загрузка региона одной кнопкой (~5–15 МБ)
- [ ] 4.3 Тест iOS Safari: `DeviceOrientationEvent.requestPermission()` по user gesture, `webkitCompassHeading`
- [x] 4.4 «Фото с подписями»: снимок + запечённый оверлей + координаты/дата → файл в «Загрузки»
- [x] 4.5 Публичное демо на GitHub Pages: [agran.github.io/vershiny](https://agran.github.io/vershiny/),

- [ ] 4.6 Анонс: пост на Хабр / форум OSM

**Критерий MVP:** в горах без сети: открыл → навёл → подстроил свайпом → сохранил фото.

## Критерии приёмки MVP

Продукт готов к публичному анонсу, когда выполнено всё ниже.

**Функциональные**
- [x] Загрузка региона Приэльбрусье одной кнопкой, объём ≤20 МБ (8.2 МБ; медиана по 124 регионам — 13 МБ)
- [ ] Панорама 360° рендерится ≤1 с после фиксации позиции (телефон среднего класса)
- [ ] Подписи: ≥90% пиков из контрольного списка (20 вершин Приэльбрусья) показаны
      с верными названием/высотой/расстоянием (±5%)
- [x] Ручная подстройка азимута свайпом; силуэт совмещается с реальным горизонтом
- [ ] Работа в авиарежиме после загрузки региона (полевой тест!)
- [x] Фото с запечёнными подписями + координатами (координаты и время — по желанию, в настройках)
- [x] Ручной выбор точки наблюдения на карте

**Нефункциональные**
- [ ] iOS Safari (последние 2 версии): запрос разрешений, корректный heading
- [ ] Android Chrome: то же
- [x] В офлайне сетевых запросов нет вовсе; онлайн вне загрузки региона — один

- [x] bundle приложения (без данных) ≤300 КБ gzip — **~58 КБ** (main 32, worker 8, sw 1, остальное — по требованию)

## Риски и митигация

| Риск | Вероятность | Митигация |
|---|---|---|
| iOS Safari: разрешение на ориентацию, кривой compass heading | Высокая | Тест с недели 1; ручная подстройка всегда доступна |
| Магнитометр врёт на 30°+ (часть Android) | Высокая | Свайп-подстройка; v1.1 — калибровка по солнцу |
| GPS в ущельях ±50–100 м | Средняя | Ручной выбор точки; для дальних пиков некритично |
| Дыры SRTM в высокогорье | Средняя | Только void-filled источники (этап 0.2) |
| Регионы севернее 60°N вне SRTM | Факт | Мульти-источник DEM (этап 0.1) |
| CV-калибровка нестабильна | Средняя | Отложена в v2.0, не блокирует продукт |
